# Component mechanics

The exact rules behind the component checks for which `className` tokens warn, and the `component.json` `motion` declaration. Moved out of AGENTS.md, which keeps the rules an agent acts on and links here.

## Appearance classes warn

A `className` token warns when, after removing variants (split on `:` outside `[...]`) and a leading or trailing `!`, its base matches `/^(bg|text|border|rounded|shadow|font|ring|from|via|to|fill|stroke)-/` or is exactly `border`, `rounded`, `shadow` or `ring`, or when `dark` appears at any variant position. Ordinary layout classes (`mt-4`, `w-full`, `grid-cols-2`, `size-4`) never warn, and neither do text wrapping, text overflow and table layout classes that share a prefix (`text-wrap`, `text-nowrap`, `text-balance`, `text-pretty`, `text-ellipsis`, `text-clip`, `border-collapse`, `border-separate`, `border-spacing-*`).[^a-layout-classes] Alignment classes (`text-left|center|right|justify|start|end`) also warn, and the message points to the component's `align` prop where one exists (the `alignHint` argument), or else shows the class on a parent element. Hints are exact code, such as `tone="destructive"`. A component may pass a hint function that picks the fix from the offending token (`registry/ouro/lib/ouro/appearance-hints.ts` maps `bg-red-500` to `tone="destructive"` and `text-lg` to `size="lg"`); pass hints only in development (`process.env.NODE_ENV !== "production" ? hint : ""`) so their text is stripped.

## Motion declarations

- A component's motion is declared in its `component.json` `motion`, per stem: `{ "states": { "<attribute>[=<value>]": { "kind": "motion" | "gesture-settle" | "none", "parts"?: { "<part>": { "properties": [...], "reduced": [...] } }, "tests": ["<file>::<full test name>"] } }, "transitions"?: [{ "from", "to", "interrupt", "tests" }], "gestures"?: [{ "name", "tests" }] }`. A state is one of `STATE_ATTRIBUTES` (`test/motion.ts`, from `scripts/motion-states.mts`); every other `data-*` is metadata.[^a-motion-states] Each animated part carries `data-ouro-part`, alone when it is no control (Checkbox's `tick`); `reduced` lists what still runs with reduced motion and may be `[]`.[^a-motion-parts] Each helper fails unless the part, or an element around it inside the part's own component root (`[data-ouro]`), carries the state's attribute when it is called (Checkbox's `data-invalid` is on that root, its Field, around the box; a checked row or an open overlay around the component does not count), so a test renders outside the state and then changes into it: a part that mounts in its state proves nothing.[^a-motion-state] A transition the browser cancels counts only when an equal one takes its place (running at the helper's next read, or, on a slow frame, a transition of the same property, or a CSS animation of the same name, on the same element that began after the cancellation and ended uncancelled before that read, seen through its transition or animation events) or it had run 90% of its duration in time (elapsed, not eased progress).[^a-motion-cancel] `test/motion.test.ts` renders each mapped component's stories, as they render and after each control is clicked once, and fails on a `STATE_ATTRIBUTES` attribute on the root or an animated part that the map leaves out, so give a state a story when none reaches it (Checkbox's `ReadOnly`).[^a-motion-stories] The named tests prove it with the test kit's `expectMotion` (exactly those properties, once per part, under both reduced-motion settings for a `motion` state) or `expectNoMotion` (an explicit empty set), which record into the test's meta; `scripts/motion-reporter.mts` writes each run's records to `.tmp/motion/<project>.<shard>.<worker>.json`, and `pnpm motion:coverage` (after `pnpm test`, and in CI's `ci` job's Motion coverage step over the uploaded partitions) fails on a property missing or extra for a (stem, part, state, reduced), a named test that recorded nothing (unexercised) or never ran (stale), a record the map does not declare, and a `motion` state with no reduced-motion record.[^a-motion-coverage] `scripts/components.mts` (`readMotion`) rejects an unknown kind or state, a part the stem never renders, a duplicate property and a test title its file does not hold; `pnpm controls:matrix` also writes `test/generated/motion-matrix.json`.[^a-read-motion] Components without `motion` are not checked yet.
