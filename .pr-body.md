A conversation in `MessageList` is now one Tab stop. Before, an app that wanted keyboard access to its messages wrapped them in focusable elements of its own, which X-ray does not outline, and crossing a channel took many Tabs.

What changes, on [the MessageList page](https://ui.ouro.bot/docs/message-list/):

- Tab lands on the newest message in view, or on the one focused last while it shows.[^tab] The messages carry a roving tabindex.
- The up and down arrows, Home, End, Page Up and Page Down move between messages, with the focus ring Ouro's controls use. A message taller than the list scrolls through first.
- The right arrow (the left one, right to left) goes into the focused message's toolbar, such as `Message`'s action bar, else its first control.
- Tab passes over the other messages' controls, so the Tab after the current message's controls leaves the list.
- A new message leaves focus where it is. When the focused message goes, focus goes to the message now in its place.
- Articles carry `aria-posinset` and `aria-setsize`; an app's own values stand. I left out `role="feed"`, because a feed holds only articles and apps put day separators and notes between messages.
- `onMessageKeyDown(message, event)` hands an app the keys pressed on the focused message, such as digits for quick reactions.[^keys] `event.preventDefault()` keeps the list from acting on the key.
- "Jump to latest" moves focus to the newest message.[^jump]

The `Keyboard` story, the docs demo (press L on a message to like it), an end-to-end spec, an agent-type snippet and a changes fragment are included. The conformance helper `controlRole` names an `<article>` an article, so a focusable message is not held to a button's edge under forced colours.

Note for the Message chat layouts in #289: Message's touch `tap` skips a press whose target is inside `[tabindex]`, and a message in a list now carries a tabindex itself, so that check needs to leave the article out once both land.
