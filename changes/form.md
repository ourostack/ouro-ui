- New: `Form`, a `<form>` that validates with the browser's own constraints and takes `errors` by field name (`errors={actionData?.errors}`). Each message shows on the field with that `name`, linked through `aria-describedby` in the server HTML too, and when errors arrive focus moves to the first field with one. The `form` key, and any key no field is named, shows in an alert at the top of the form. Server errors only show: they never block the next submit. A Form's submit stops at that Form, so a Form in a sheet never submits the Form the sheet sits in. `action` and `method` pass through, and `render={<RouterForm />}` submits through React Router.
- New: `EditSheet`, a `Dialog` with a `Form` inside (a bottom sheet on phones): `onSubmit` gets the fields as `FormData` and may return errors or a promise; the save button shows `loading` while it runs and the sheet cannot be dismissed, errors land on their fields, a failed save shows `failureMessage`, and success closes it and returns focus to the trigger. Dismissing it after an edit asks inside the sheet first (`discardMessage`, `discardLabel`, `keepEditingLabel`).
- `Field` (and every control built on it) shows a `Form`'s error for its `name` when it has no `error` of its own, and drops it once the user changes the control. A Field's `error` now only shows: it no longer marks the control invalid to Base UI, so it never blocks a form's next submit (the browser's own checks still do). The label now has an id of its own (`<id>-label`).
