# Ouro UI

React components with handcrafted interactions, designed for coding agents to use correctly without a skill.

```sh
pnpm add @ouro.bot/ui motion
```

```tsx
import "@ouro.bot/ui/styles.css";
import { Button, Dialog } from "@ouro.bot/ui";

<Dialog title="Edit recipe" trigger={<Button>Edit</Button>}>
  <RecipeForm />
</Dialog>;
```

`react` and `react-dom` 19 and `motion` 12 or later are peer dependencies. The stylesheet needs no Tailwind setup and has no reset.

## For agents

Everything you need is in this package. Each component has a page in `docs/` (in `node_modules/@ouro.bot/ui/docs/`) with its purpose, an example, every prop, its modes and what to use instead. The same text is in the JSDoc, so your editor shows it on hover, and the readable source is in `src/`.

- **Props first.** Each component's props describe the whole thing. Parts from `@ouro.bot/ui/parts` are an escape hatch, only for layouts the props cannot express.
- **What always applies is required.** A Dialog or Sheet needs a `title`; hide it with `hideTitle`.
- **Appearance comes from named props**: `tone` (`neutral`, `accent`, `success`, `warning`, `danger`), `variant` and `size`. There are no color names.
- **`className` is for layout only**: margins, width and grid placement. Your classes always win. Appearance classes (`bg-*`, `text-<color>`, `rounded-*`, `font-*`, `dark:*`…) warn in development with the prop to use instead.
- **The prop you guess is the prop that exists**, or it is typed `never` with a pointer to the real one: `isLoading` says to use `loading`.
- **Modes follow the types.** `href` makes a Button a link; a Dialog takes either `trigger` or `open` with `onOpenChange`.
- **Dev messages teach**, in one format: `[ouro-ui] <Component>: <what's wrong>. Fix: <exact code>.` They are stripped from production builds.

### Actions

- **Button** — A button, or a link styled as one. [Docs](docs/Button.md)

### Text

- **Heading** — A section title, `<h1>` to `<h6>`, in the theme's display font. [Docs](docs/Heading.md)
- **Text** — Body text in the theme's type scale and colors. [Docs](docs/Text.md)

### Overlays

- **ConfirmDialog** — Asks the user to confirm an action, with Cancel focused first. [Docs](docs/ConfirmDialog.md)
- **Dialog** — A dialog that presents itself for the screen: a centered dialog on wider screens and a bottom sheet you can drag away on phones (below 640px). [Docs](docs/Dialog.md)
- **Sheet** — A panel that slides in from an edge and is dragged back to dismiss: the mobile form of a dialog. [Docs](docs/Sheet.md)

### App setup

- **OuroProvider** — Optional app-level provider that routes internal `href`s through your router's link. [Docs](docs/OuroProvider.md)
- **ThemeScript** — Sets `data-theme` on `<html>` before the first paint, so a stored dark preference never flashes light. (from `@ouro.bot/ui/theme`) [Docs](docs/ThemeScript.md)
- **defineTheme** — Builds a theme: the full token set (your overrides over the Ouro defaults) and the CSS custom properties that apply it. (from `@ouro.bot/ui/theme`) [Docs](docs/defineTheme.md)

### Parts

- **Parts** — building blocks from `@ouro.bot/ui/parts`, only for layouts the props cannot express. [Docs](docs/parts.md)

## Theme

`defineTheme` builds your tokens into CSS, and `ThemeScript` applies a stored light or dark preference before the first paint. Both come from `@ouro.bot/ui/theme`, which is safe to import on the server. See [docs/defineTheme.md](docs/defineTheme.md) and [docs/ThemeScript.md](docs/ThemeScript.md).
