# Guardrails

The guardrail kits hold an app to Ouro UI. The **census** (`ouro-census`) measures the running app, page by page and state by state, and the **source rule** (`ouro-source-rules`) reads the app's source and finds the controls still built by hand: their aim is that every control a person can reach is an Ouro control, and the number that are not can only fall.[^ratchets] Each of those two keeps a committed baseline, so every change is a reviewed diff, and each refuses a rise unless you record why.[^baselines] The **screen check** (`ouro-check`) opens the built app's pages at screen sizes from a phone to a wide desktop and finds what a person would see broken.[^check-rules] It keeps no baseline: it fails on any finding that `ouro-check.json` does not waive with a reason, or record as known when an update brought its rule.[^check-exit][^check-known]

Add them from the same place and release tag as your components:

```sh
npx shadcn@latest add ourostack/ouro-ui/ouro-census#v1.3.654 ourostack/ouro-ui/ouro-source-rules#v1.3.654
```

`ouro-census` installs `e2e/ouro-census/` and names `@playwright/test` and `axe-core` as devDependencies. `ouro-source-rules` installs `scripts/ouro-source-rules.mjs` and names `typescript` and `postcss`. Like the test kit, they carry no version, so the CLI installs a package only when your app lacks it.[^kit-versions] The census reads names with axe-core and needs 4.13.0 or later: on an older one it throws before it loads axe into the page, naming the version it found.[^census-axe]

## The census

A control's identity is one line: its role, its accessible name, its Ouro marker and part (`data-ouro-control` / `data-ouro-part`, `-` when there is none) and its context, the nearest landmark, dialog or named group, else the nearest `data-testid`.[^identity] Never its position:

```text
button "Save" [button/root] in main
option "Weekly" [select/item] in dialog "Repeat"
link "Notes" [-/-] in testid "note-actions"
```

A state's census is the exact multiset of its visible controls. Whitespace in names collapses, and a relative time ("2 minutes ago") or a calendar date ("Jun 1, 2026") becomes `<relative time>` or `<date>`, so a name never depends on when the run happened.[^names]

### List the journeys

A journey is a page your app renders, as the visitor who sees it, and the states a person can open on it: dialogs, menus, sheets, popovers, disclosures. Each state starts from a fresh load of the journey's `path`.[^fresh-load] Write its `action` to only open things, never to submit, so the census leaves your test data alone.

```ts
// e2e/census.spec.ts
import { test as base } from "@playwright/test";
import { censusTests, type Journey } from "./ouro-census/census-page.mjs";

// Declare the census in this spec, not in the kit: Playwright lists a test under the file that calls
// `test()`, so `playwright test e2e/census.spec.ts` finds the kit's own calls under no file.[^locate]
const wrap = <T extends (...args: any[]) => unknown>(fn: T): T => ((...args: any[]) => fn(...args)) as T;
const test = Object.assign(wrap(base), {
  describe: wrap(base.describe),
  beforeAll: wrap(base.beforeAll),
  use: wrap(base.use),
});

const journeys: Journey[] = [
  { id: "home", enrolled: false, path: "/", states: [{ id: "default" }] },
  {
    id: "note",
    enrolled: true,
    path: "/notes/1",
    storageState: "e2e/.auth/writer.json",
    states: [
      { id: "default" },
      {
        id: "delete-dialog",
        action: async (page) => {
          await page.getByRole("button", { name: "Delete" }).click();
          await page.getByRole("alertdialog").waitFor();
        },
      },
    ],
  },
  { id: "not-found", enrolled: false, path: "/no-such-page", status: 404, states: [{ id: "default" }] },
];

censusTests({ test, journeys, projects: ["chromium", "webkit"], componentsDir: "src/components/ouro" });
```

`projects` lists every Playwright project the spec runs in; a run that leaves one out fails the merge.[^merge-projects] `componentsDir` is where your app installs Ouro components: a marker naming no file there fails an enrolled journey.[^known-items] Pass `prepare` to wait for hydration after each load, and a `test` your spec declares with your fixtures (the wrapper above is the minimum). Each test fails when the page answers another status (`status`, 200 by default) or redirects, since it would measure some other page.[^status]

### Run it and accept changes

Each worker writes its census to `ouro-census/` (or `OURO_CENSUS_DIR`).[^worker-files] After the run, merge them and keep the result as the run's artifact, pass or fail:

```yaml
- run: npx playwright test e2e/census.spec.ts
- if: ${{ !cancelled() }}
  run: node e2e/ouro-census/census-merge.mjs ouro-census census-actual.json
- if: ${{ !cancelled() }}
  uses: actions/upload-artifact@v4
  with:
    name: ouro-census-actual
    path: census-actual.json
```

The merge fails, writing nothing, when any project skipped a state, recorded one twice, or recorded one the list lacks.

Each state must equal `e2e/ouro-census/census.baseline.json` exactly: an added, removed, renamed, re-marked or duplicated control fails with a diff, and a state the baseline lacks fails with "no baseline".[^exact] To accept a change, rewrite the baseline from the run and commit it:

```sh
node e2e/ouro-census/census-update.mjs <run-id>          # downloads the artifact with gh
node e2e/ouro-census/census-update.mjs census-actual.json # or reads a local file
```

The census must be deterministic. Before baselining new journeys, run the same commit twice and compare: `node e2e/ouro-census/census-compare.mjs <run-id> <run-id>` fails, naming every difference, unless both runs recorded the same multisets. Measure lists of run-specific data (this run's users, anything another test creates) in a state that cannot show it, such as a search that matches nothing.

### Enrol and ratchet

An enrolled journey fails on any control without an Ouro marker. An unenrolled one is measured, and its unmarked count may only fall, state by state on each project: a fall in one state never pays for a rise in another.[^per-state] The update refuses a rise unless `--allow-regression "<reason>"` says why, and records it under `$allowedRegressions` until the next update. It also refuses to drop a journey or state the baseline has unless `--remove <journey>` (or `<project/journey/state>`) names it and `--remove-reason "<reason>"` says why; a renamed journey is a drop plus a new one, and may not start with more unmarked controls than the one it replaces. Set `enrolled: true` on a journey once its controls are all Ouro's.

## The source rule

The source rule reads every `.ts` and `.tsx` file under your source folder with the TypeScript compiler, and every `.css` file with PostCSS, skipping the Ouro installs (`components/ouro/`, `lib/ouro/`), tests, stories and declarations.[^scan] It finds:

- a raw `<button>`, `<a>` (and React Router's `Link`), visible `<input>`, `<select>`, `<textarea>`, `<details>`/`<summary>`; a hidden input and the anchor Ouro's `Link` renders through `OuroProvider` are exempt;
- `contentEditable`, a positive `tabIndex`, an interactive `role=`, and click, key, pointer or touch handlers on a plain element;
- any `data-ouro*` attribute your code writes, except the ones Ouro check asks you to write: `data-ouro-session`, `data-ouro-allow`, `data-ouro-allow-why`, `data-ouro-check-press`, `data-ouro-check-no-press` and `data-ouro-reveal`;[^app-markers]
- elements from another UI-control library (Headless UI, Radix, Base UI used directly, React Aria, Ariakit, MUI, Chakra, vaul, cmdk, sonner);
- control-state styling: `focus:`, `active:`, `aria-pressed:`, `data-[state=open]:` and the like in a `className`, and stylesheet rules that put such state on a class or a `data-*` hook;
- every use of a component of yours that renders any of these, however deep the wrapping.[^wrappers]
- an index built in render (`render-index`): `new Map(…)`, `new Set(…)`, `new RegExp(…)`, `Object.fromEntries(…)`, `Object.groupBy(…)` or `Map.groupBy(…)` with an argument, evaluated in a component's own body (a capitalised function in a `.tsx` file, also through `memo` or `forwardRef`), a custom hook's or a class's `render`.[^render-index] An all-capitals function such as a route handler's `GET` is no component.[^render-index] A component rebuilds it on every render, a keystroke or a hover included, so build it where its data changes, once per change: in the store or loader that holds the data, or in `useMemo` on its inputs; move a constant to module scope.[^render-index] Anything inside a nested function passes: a `useMemo` or `useEffect` callback, a lazy `useState(() => …)` initializer, an event handler.[^render-index] An empty `new Map()` passes too.[^render-index] A callback that runs during render, such as `rows.map((row) => new Set(row.tags))`, is not counted yet.[^render-index] Like a spinner, an index counts where you write it and never makes the component around it a hand-rolled control.[^render-index]
- an animation of a layout property (`layout-animation`): `transition-all`, a `transition-[…]`, `[transition:…]` or `[transition-property:…]` class that names width, height, an inset, a margin or padding, a border width, a gap, flex, grid tracks, font size or line height, a `transition` style value or a stylesheet `transition` that does (a shorthand with no property animates `all`), keyframes for an element's `animate()` or Motion's `animate`, `exit` and `while…` props that set one, and `@keyframes` that set one.[^layout-animation] Those properties make the browser lay the page out again on every frame, on the main thread, while transform and opacity are the properties the compositor animates alone, so an overlay, a menu or a hover effect that moves or fades with them stays smooth on a slow machine.[^compositor] Animate `transform` (translate, scale) and `opacity` instead, and name the properties a transition runs (`transition-[opacity,translate]`, `transition-opacity`, `transition-transform`) rather than `transition-all`. Tailwind's plain `transition` and `transition-colors` pass, and so does a shorthand that animates nothing: keywords only (`unset`, `initial`, `inherit`, `revert`), or a zero or missing duration.[^layout-animation] Ouro's own Accordion, Collapsible and Checklist animate a height or grid rows on purpose, since the content below them must move; `scripts/layout-animation-allowed.json` lists them with why.[^layout-allowed]
- a hero drawn by hand (`hand-drawn-hero`): a `section` or `header` whose class names a hero. Use the registry's `Hero` instead (`<Hero title="Welcome" picture={picture} />`), so a change to heroes reaches it too.[^hand-drawn-hero]
- a spinner standing where content would (`content-spinner`): Ouro's `<Spinner>` or any element with an `animate-spin` class that is returned or assigned on its own, or is the only thing in its element. Show a `Skeleton` shaped like the content instead (`<Skeleton shape="row" count={6}>`), so the content takes its place and nothing moves when it arrives. Inline progress for an action passes: a spinner inside a button, in a prop (a field's adornment, a control's icon), in an object (a toast's or a menu entry's icon), or beside the words that say what is under way. A spinner counts where you write it and never makes the component around it a hand-rolled control.[^content-spinner]
- a round picture or monogram drawn by hand (`hand-drawn-avatar`): an `img` or `overflow-hidden` element of avatar size with `rounded-full`. Use `<Avatar name="…" src="…">`, with `shape="square"` for a team or channel and `shape="agent"` for an AI agent, so every app draws people, teams and agents the same way.[^hand-drawn-avatar]
- a small round dot drawn by hand (`hand-drawn-presence-dot`): an empty `rounded-full` element of dot size with a background color. Use `<Avatar presence="online" presenceLabel="Online">` for presence; a count belongs in a `Badge`.[^hand-drawn-presence-dot]
- a small round accent-colored dot in a row, which is an unread mark (`hand-drawn-unread-dot`). Use `<UnreadDot label="Unread" />`, the dot ConversationList and Command draw.[^hand-drawn-unread-dot]
- a load that waits for focus, visibility, the person's return, idle time or scrolling (`gated-load`): a fetch, a load, prefetch or refetch call, a data hook, `import()`, `new Image()` or a `src` set inside a `visibilitychange`, `focus`, `blur` or `pageshow` listener on the window or document, under a `document.hidden`, `visibilityState` or `document.hasFocus()` condition, in a `requestIdleCallback`, an `IntersectionObserver` or an in-view or idle hook's callback, or waiting on what such a hook returns (`enabled: inView`) or on state such a callback sets from what the gate says (`setShown(entry.isIntersecting)`); a popover that closes on blur (`setOpen(false)`) leaves `open` ordinary; and an element's `loading="lazy"`, or an address that waits on a gate (`src={inView ? url : undefined}`). Load it eagerly instead ([Load eagerly](#load-eagerly)). A gate that only changes what is drawn passes, because it loads nothing: pausing an animation or a caret, windowing rows whose data stays loaded, or a media stream. So does saving as the page hides (`sendBeacon`, or a `fetch` with `keepalive` or a method other than GET). It counts where the load is written and never makes the component around it a hand-rolled control.[^gated-load]
- a corner radius fixed by hand (`hand-drawn-corner`): an arbitrary class such as `rounded-[12px]` or `rounded-t-[0.5rem]`, an inline `borderRadius` in a `style` prop, a stylesheet `border-radius` that is not a theme variable or a circle (a rule for a dot, thumb, ring or pill is left alone), or `rounded-full` on a large oblong box or a structural element that is not a dot, pill, thumb or ring, on a plain element. Take the radius from the theme instead, so a change to the theme reaches it too. A drawn shape that must keep its own corners (a speech bubble) sets `corner-shape: round` in its rule, or follows a `/* ouro-allow hand-drawn-corner: <reason> */` comment that gives a reason, placed directly before its rule or first in the stylesheet.[^hand-drawn-corner]
- a switch drawn by hand (`hand-drawn-switch`): an intrinsic element with `role="switch"`. Use the registry's `Switch` instead (`<Switch label="Mute" checked={on} onCheckedChange={setOn} />`), so a change to switches reaches it too.[^hand-drawn-switch]
- vague failure copy (`vague-failure-copy`): a string, a template literal or JSX text that says "couldn't", "could not", "something went wrong", "unable to", "failed to load" or "an error occurred", or whose whole text is a bare "Error" or "Upload failed". See [Say precisely why it failed](#say-precisely-why-it-failed).[^vague-failure-copy]

Each offender is a fingerprint, `file::component::category::tag::props`, never a line number, so moving code keeps it.[^fingerprints] Record where your app starts, commit the baseline, then check on every change:

```sh
node scripts/ouro-source-rules.mjs --write-baseline   # the first write records the starting point
node scripts/ouro-source-rules.mjs                    # fails on any difference from the baseline
node scripts/ouro-source-rules.mjs --base origin/main # on a pull request: also no rise against main
```

A new offender fails: use an Ouro component instead, or add the missing one to Ouro UI first. A fixed one fails until `--write-baseline` removes it. Against `--base`, a rise needs `--write-baseline --base <ref> --allow-regression "<reason>"`, which records it for that pull request only. Moving code is neutral: an offender removed and added with the same category, tag and literal props, in the same file or the same component, pairs one-to-one.

Against `--base`, the settings are read at the base too: its `baseline` setting says where its baseline is, and a pull request may only widen what is read. Moving the baseline, another `src`, an `ouroDirs` or `exclude` entry the base did not already skip, a `failureCopyAllow` match that is not already covered by a match at the base, or a set or changed `hookPrefix` fails like a rise, and needs the same `--allow-regression "<reason>"`, which records it. A missing baseline is a first baseline, written without a reason, only when the base has neither `ouro-source-rules.json` nor a baseline.

Settings are optional, in `ouro-source-rules.json` at the root:

| Setting | Default | What it sets |
| --- | --- | --- |
| `src` | `src`, or `app` without one | The folder it reads. |
| `ouroDirs` | `<src>/components/ouro/`, `<src>/lib/ouro/` | Where your app installs Ouro UI; never read.[^scan] |
| `exclude` | none | More folders not to read, such as generated code. |
| `hookPrefix` | none | Read stylesheet state only on your own hooks (`.app-…`, `[data-app-…]`), not on every class. |
| `baseline` | `ouro-source-rules.baseline.json` | Where the baseline lives. |
| `failureCopyAllow` | none | Failure copy that is already precise: `[{ "match": "<part of the text>", "reason": "<why this wording is precise>" }]`. A text holding a `match` (case-sensitive) passes; an entry with an empty `match` or without a `reason` stops the rule. |

### Say precisely why it failed

A failure message tells the person, or the agent, what happened and precisely why (the system and its answer), who or what caused it where you know, and the next step as a working action or command. When you don't know the cause, say what you tried and what came back.

| Before | After |
| --- | --- |
| `Couldn't show this picture` | `The photo service says this picture was deleted by its owner. Ask them to share it again.` |
| `Something went wrong` | `The server didn't answer within 60 s. Your draft is saved; press Send to try again.` |
| `Unable to open file` | `You don't have access to this file. Ask its owner for edit access.` |
| `Error` | `inbox-agent stopped: the mail service turned down its sign-in (401). Sign in again in Settings.` |

The rule reads strings, template literals and JSX text in your source. It skips what is not copy: import specifiers, types, object keys, tagged templates (`css` and `gql` ones), compared values, `className`, `data-*`, `id`, `key`, `type`, `href`, `src`, `to`, `name`, `role`, `htmlFor` and `as` values, and a string that is one lowercase word (`"error"` as a status). A count such as `{n} failed`, a negation such as "No errors" and an action such as "Retry failed" are not bare failures.[^not-bare] A phrase passes when its cause follows in the same sentence, after a colon, a dash or "because", in at least two words that start with neither a next step nor a vague word, and "Error: …" is held to the same test.[^not-bare] So `Couldn't send: you're offline. Try again when you're back online.` passes, and `Couldn't send: try again.` and `Something went wrong. Error code: E42` do not. JSX text is read with what follows it, so `<p>Couldn't send: {why}</p>` passes like its template literal.[^not-bare] Text you build from pieces or load from a JSON catalog is not read. It also skips the first argument of `includes`, `startsWith`, `endsWith`, `has` and `test` (a string matched against, not shown), a string in a `new Set([...])` that is only used for `.has(…)` membership, and the class name in `error.name || "Error"`.[^vague-skips] A heading or label that only names the topic, such as "Errors" or "Machine errors", is not a bare failure either: a plural with at most two words before it and no action among them.[^vague-skips] When a message names the system and its answer and still holds one of the phrases ("The card service says your card could not be charged. Use another card."), add it to `failureCopyAllow` with its reason.[^vague-failure-copy] A single text can instead keep its wording with a comment on the line before it or on its own line, `// ouro-allow vague-failure-copy: <reason>` (`{/* … */}` in JSX), counted as `vague-failure-escape`, so a new one rises against `--base` and needs `--allow-regression "<reason>"`, as a new `failureCopyAllow` match does.[^vague-escape] A message a protocol mandates, such as JSON-RPC's `"Parse error"`, is not skipped: it goes in `failureCopyAllow` with its reason too.[^vague-skips]

Prior art:

- [Nielsen Norman Group's error-message guidelines](https://www.nngroup.com/articles/error-message-guidelines/ "verify:urlOk(https://www.nngroup.com/articles/error-message-guidelines/)"): adopt. Say precisely what went wrong in plain words, and offer a way forward.
- [GOV.UK's error message component](https://design-system.service.gov.uk/components/error-message/ "verify:urlOk(https://design-system.service.gov.uk/components/error-message/)"): borrow. Its wording rules are for form fields, but its stance carries over: say what happened and how to fix it, in place of "an error occurred".
- [Apple's Human Interface Guidelines on alerts](https://developer.apple.com/design/human-interface-guidelines/alerts "verify:urlOk(https://developer.apple.com/design/human-interface-guidelines/alerts)"): watch. It governs when an alert appears and how its buttons read, more than what a failure says.

### Load eagerly

Load intelligently and eagerly. Don't gate a fetch on focus, on visibility or on the person coming back to the window: a person who returns to an app and then waits for what it could have fetched while they were away has had a bad experience. Start a load as soon as you know the data will be needed: on mount, or as soon as the page before it lands. Spend the work on what the person is likely to look at next, newer before older, and keep it within the performance budgets that [the screen check](#the-screen-check) measures (`first-content` and `inp`).

The source rule's `gated-load` category finds the loads that wait.[^gated-load] When one has to wait, for a reason the rule cannot see, record the reason against the base: `node scripts/ouro-source-rules.mjs --write-baseline --base origin/main --allow-regression "<reason>"`.[^gated-load-escape]

## The screen check

The aim is every state handled and checked.[^check-states-lead] The check is the floor under it. It opens the pages and the states you list, and it finds the broken ones that measurement can decide.[^check-states] A person still judges the rest, as the end of this section says.

The screen check (`ouro-check`) opens every page of your built app in headless Chromium at every screen size from a 320px phone to a 3840px screen, and four short landscape screens, light and dark, at density 2 up to 3072px wide, the widest real 2x screen, and 1 above it, so a 3840 screen asks for the pictures a 4K monitor shows.[^check-sizes] Each finding records the density it was found at.[^check-sizes] It finds six things, by measurement rather than by looking at pictures:[^check-rules]


A clean report is the floor: what measurement can decide about the screen isn't broken. It can't see whether people understand the screen or finish its task, such as whether they know a form saved or what an action will remove. Say a screen passes Ouro check, and before you call it good, watch a few people do its task.[^check-floor] Before a person sees it at all, pass the beauty gate in [Design craft](design-craft.md#the-beauty-gate).

The report itself ends with a "Needs a person" list: questions only a person can answer, drawn from the components on each page.[^check-needs-a-person]

While a modal is open (`aria-modal="true"` or a modal `<dialog>`), the layout, text and design rules check only the modal: the page behind it is out of reach and laid out for the modal, so its findings are left to the page's own run, as it is once the modal closes.[^check-behind-modal]

| Rule | What it finds |
| --- | --- |
| `overlap` | A line of text drawn over another line, or over a picture, in the same section. The part of a picture a clipping box cuts away doesn't count, and a label on an opaque backing of its own, such as a chip on a picture, reads.[^check-overlap-picture] So does text on a glass scrim, a fill of 60% or more with the picture blurred behind it, around the text or as a layer of its own beneath it, as Card's rising title lies on.[^check-overlap-glass] An opaque overlay (an open dialog, menu, listbox, popover or tooltip, or a panel of 120×48 or more floating over the page, not a badge) covers the page text under it, as a sticky bar does.[^check-overlay] |
| `sideways-scroll` | A page wider than the screen, naming the outermost elements that stick out. |
| `clipped-text` | Text cut off by its box. An ellipsis or a line clamp is truncation on purpose and passes while the whole text is still there: in a `title`, an `aria-label`, or the text itself in the accessibility tree.[^check-truncate] Text behind an open modal is the page's, hidden on purpose until the modal closes, so its ellipsis passes too.[^check-overlay] A text block, a heading or a picture with less than 90% of its box shown, cut by the nearest ancestor that hides its overflow (`overflow: hidden` or `clip`), such as a title pushed partly above its card.[^check-clipped] It is measured by box: a picture cropped by `object-fit` inside a box that fits it passes, and so do text inside a scroll container or a carousel (which scrolls it rather than cutting it) and a visually hidden label (`clip-path: inset(50%)`, or the sr-only pattern).[^check-clipped-pass] |
| `long-lines` | Off unless `ouro-check.json` declares a measure; then the elements it names whose lines run past it. Columns side by side are lines of their own, and a run of short items set apart by middle dots, bullets or bars is a list, not prose.[^check-measure] |
| `narrow-text` | Prose that wraps onto two lines or more and is held by its own `max-width` (or one above it, below the nearest flex or grid box or `main`) to under about three quarters of the column it sits in, where that column is at least 900px wide.[^check-narrow-text] The cap has to be what holds the box: a sidebar, a grid column, a card, a table cell or a dialog that is narrow by its layout passes, and so does centred text.[^check-narrow-text] Declare a measure in `ouro-check.json` when the design sets one, and the text passes.[^check-narrow-text] |
| `blurry-image` | A picture drawn larger than its file's own pixels allow at the screen's density, often a wrong `sizes` on a cropped, height-driven image. The drawn width times the density must be no more than the file's width, with half a pixel for rounding.[^check-blurry-exact] A raster CSS background counts too, at its `background-size`, each layer and an `image-set`'s finest file.[^check-blurry-background] It cannot be waived: see [A blurry picture can't be waived](#a-blurry-picture-cant-be-waived).[^check-blurry-unwaivable] |
| `stretched-image` | A picture or a video drawn out of its own shape, by more than 5% and 2px: a width and a height that don't keep its ratio, with nothing to crop or fit it (`object-fit` is `fill`, an `<img>`'s default).[^check-stretched] Small pictures count too, since a squashed avatar or icon is as plain to see as a large one.[^check-stretched] |
| `image-fade` | A picture that fades into the page: an `<img>`, an SVG `<image>` or a `url()` background with a gradient mask on it or on a box around it that fades it, or with a gradient between transparent and a colour over a tenth of it or more, from an absolutely positioned overlay or a `::before` or `::after` of the picture or a box around it.[^check-image-fade] A radial or conic gradient counts only when it is opaque at its outer edge, as a vignette is; a glow that fades out adds light, and passes. A linear mask is read along its line, so a picture outside the bands where it isn't opaque, such as the middle of a list that fades at its edges, passes; a mask the check can't read that way (radial, diagonal, sized or placed) counts as fading every picture under it.[^check-mask-ramp][^check-image-fade] See [Pictures end on a hard edge](#pictures-end-on-a-hard-edge). |
| `axe` | Serious and critical axe-core violations, at a phone and a laptop size. Base UI's focus guards are left out, as the axe kit's `axeExclude` leaves them out: they hand focus on the moment they get it.[^check-guards] |
| `broken-image` | A picture that loaded empty: a missing file, or one that is no picture.[^check-pages] |
| `http-error` | A page that answered with a status other than 2xx, or did not answer.[^check-pages] |
| `not-ready` | A page that gave no ready signal in time.[^check-pages] It is checked as it is, but never passes.[^check-pages] |
| `console-error` | An uncaught error or rejection, or a `console.error` or `console.warn`, React's warnings among them, while the page loads and is checked, named by its first line.[^check-runtime] |

### Design rules

The check also holds pages to design rules that measurement can decide, after Refactoring UI (Wathan and Schoger). Each came from a page a person found wrong, and each has a fixture that fails and one that passes:[^check-design] They judge only what is drawn: a box counts as the part of it its clipping boxes leave, and one scrolled out of its scroller, such as a card past the edge of a map, isn't there at all.[^check-drawn]

| Rule | What it finds |
| --- | --- |
| `giant-picture` | A banner-shaped picture (scenery, 1.8 times as wide as tall or wider) in the flow, leading a content item, such as a work entry or a card with its own heading, that outweighs its words: it fills the item's width, is over 55% of its height and over 1.25 times the height of the rest.[^check-design-limits] Show the work itself, a screenshot or the component, or a small picture beside the words. | `cramped-heading` | A heading, with the icon on its row, closer to a picture or a filled or framed box above it than half its font size (a quarter, for its own card's picture). | `nested-frame` | A frame inside a frame: a framed box hugging another within 6px on every side (a double border); or a rounded, filled or framed box whose child has an edge of its own (a fill, a frame, or a picture that runs to its corner, not an icon or a clear logo) and sits near its corner with a radius that isn't the outer radius less the inset, so the corners don't nest.[^check-design] |

| `baked-corner` | A picture or video whose own pixels draw a corner inside the page's frame (the roundest clipping box it fills, past a wrapper of zero size), such as a screen recording of a window with its dark corner showing in a rounded frame.[^check-corner-frame] Read from the pixels, on the video's first frame, at two corners or more in the same colour.[^check-design] |

| `duplicate-control` | Two controls in view with the same role and name in one place (the same section, group, nav, header, aside, form or dialog), such as two Close buttons on a panel.[^check-layout] Controls in repeated items (a list's rows, a table's cells, articles) each have their own, and pass; so do two links to the same place, and toggles that each open their own panel (`aria-controls`).[^check-layout-pass] |

| `off-scale` | A padding, margin or gap the app set to a fixed `px` or `rem` where Tailwind's `--spacing` step is defined, with the step to use (`p-6`).[^check-token-scale] Spacing in `em`, fluid spacing (`clamp()`, `min()`, `max()`, a viewport unit) and a hairline under half a step are left alone.[^check-token-scale-pass] |

### Controls a person can't use without knowing why

The check reads each disabled control for a reason the page gives for it, as Apple's [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons) guidance asks that a person can tell why a button is unavailable, and as WCAG 2.2's [Info and Relationships](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html) asks that what explains a control is tied to it, so a screen reader says it too.[^check-interaction]

| Rule | What it finds |
| --- | --- |
| `disabled-no-reason` | A disabled control (`disabled`, `aria-disabled="true"`, or in a disabled fieldset) with no reason tied to it: no `title`, no `aria-description` and no `aria-describedby` text, on it or its disabled fieldset.[^check-interaction] A hint beside it that nothing ties to it isn't enough. Three cases explain themselves and pass: a busy control (`aria-busy`, such as a loading Button), a control that moves one way (Previous, Next, Back, Later, Zoom out, Undo) at its end, and a control beside an empty field in its form or in a box up to three out, such as Send under an empty message.[^check-interaction-pass] A field on the page itself, such as a search box in the header, excuses nothing.[^check-interaction-pass] |
| `decision` | An element that breaks a decision recorded in `ouro-check.json`: see [Keep a decision as a check](#keep-a-decision-as-a-check).[^check-decision] |
| `pointer-not-control` | A pointing-hand cursor, where it starts (a child inherits it), on an element that is no control, isn't in one and holds none, such as a pane or a heading set to `cursor: pointer`: a person expects a press to do something there, and a keyboard can't reach it.[^check-pointer] |
| `linked-card-dead-zone` | A card or row that is one link (Ouro's `data-linked`, or a box around a link whose `::after` is stretched over it) where a click at some spot outside its own controls opens nothing, as when the page positions one of its parts and the link's layer stops there. The check hit-tests a grid of spots on each card, as a click would land, and runs none of the page's code.[^check-dead-zone] A card whose root opens its link from any click on it says so with `data-follows-link` and passes; Ouro's Card, Item and Table do.[^check-dead-zone] |
| `reveal-reflow` | A card whose hover or keyboard focus reveals a part (Card's `revealDescription`, an Item's `revealActions`, or `data-ouro-reveal`) and moves the card's own box or anything outside it. The check hovers each such card, then gives its link keyboard focus, and compares where everything is with where it was at rest.[^check-reveal-reflow] |

### A first run a person can't get stuck in

From a fresh install an app goes to sign-in and then to the app, and whatever the person does on the way (dismissing a dialog, pressing a control early, signing out), they mustn't end up on a blank screen, a dead end, or a signed-out window that looks like a signed-in one with nothing in it. These rules hold that on every page the check reaches, and on every state `states` reaches by presses, such as signed out.[^check-first-run]

| Rule | What it finds |
| --- | --- |
| `blank-pane` | The pane a person looks at (the open modal dialog, else the `main` landmark, else the page) draws nothing to read, nothing to press and no named progress: a progressbar, a busy region with a name (a Skeleton's), a status region with words, or words that end in "…" or start "Loading", "Signing", "Getting" and the like.[^check-blank-pane] An empty `main` that collapses to no height is still the pane, and an unnamed control that is off, a hidden word or a picture with empty `alt` holds nothing; words hidden only from assistive tech (`aria-hidden`) still count, as a person sees them.[^check-blank-pane-near] |
| `dismissable-step` | An open modal dialog (every modal dialog takes Escape) over a page that would strand the person once it goes: behind it the `main` landmark is blank, or, signed out, offers no way to sign in and no progress.[^check-dismissable-step] A required step (sign-in, a first-run setup) belongs on the page, with `AuthLayout`, not in a `Dialog` or `Sheet`, which a person can put away with Escape.[^check-dialog-escape] |
| `signed-out-empty` | A signed-out page that shows the empty state a signed-in person would see: an Ouro `Empty`, or a heading, paragraph or status that says there is nothing ("All caught up", "No messages yet"), which tells a signed-out person nothing is wrong.[^check-signed-out-empty] Signed out, show the way in instead: an `Empty` that holds it (a Sign in control, or progress) passes.[^check-signed-out-way-in] |

An app says where the person is signed out with `data-ouro-session="signed-out"` (or `"signed-in"`) on any element, its shell's root being the place; an element is judged by the nearest marker around it, else by the page's one signed-out marker.[^check-session] The rules read English words by default; an app gives its own in `ouro-check.json`'s `firstRun`, each a regular expression's source read without case, which replaces Ouro's:[^check-first-run-words]

```json
{ "firstRun": { "signIn": "^(sign in|log in)\\b", "empty": "nothing new|all caught up", "progress": "…$" } }
```

### Pressing is opt-in

`inp` presses real controls, and a press does what it says on whatever server your app talks to: a "Send", "Delete" or "Buy" pressed against a staging app connected to a real account sends, deletes or buys. So the check presses only the controls you list: those its `press` selectors match in `ouro-check.json`, and those marked `data-ouro-check-press`. With neither, it presses nothing.[^check-opt-in] Even when listed, it never presses a control with a destructive tone or inside one (Ouro's and shadcn's destructive classes, or `data-tone` or `data-variant` set to `destructive`), one marked `data-ouro-check-no-press`, a link, or a form's submit button, and it skips a listed element whose middle is one of those.[^check-press] List controls whose press only changes what the page shows, such as a tab, a disclosure or a filter, and point the check at made-up data.

It presses each listed control 5 times, or as often as `pressRepeat` says, and presses Escape after each press to close what it opened.[^check-repeat] The finding is the 75th percentile of the presses, and `report.json` records each press's time in `samples`, so one slow press on a busy machine doesn't make a finding.[^check-repeat] It presses up to 24 controls a page, at 1440×900 (or the widest size you give) in the first theme, in a browser context of its own, after the contact sheet's shot.[^check-budgets]

To press every Ouro control without listing them, set `"pressAll": true`. The check then also presses each element marked `data-ouro-control` that is a button, a checkbox, or has the role `button`, `switch`, `checkbox`, `tab` or `menuitem`, opens the page again after each one so a press cannot change the next, and presses up to 24 controls a page, or as many as `pressLimit` says.[^check-press-all] Links, form submit buttons and destructive controls are left out, as is a control marked `data-ouro-allow="inp"` with a `data-ouro-allow-why` reason. `report.json` and each finding name the control pressed.[^check-press-all] `pressAll` is off unless set.

`ouro-check.json` can list the controls and change the budgets:[^check-opt-in]

```json
{
  "press": ["[role=tab]", "[data-filter]"],
  "pressRepeat": 7,
  "budgets": { "inp": 150, "layout-shift": 0.05, "first-content": 2000 }
}
```

### States reached by presses

To check an app in views it reaches by presses, such as an open chat or a call, list them under `states` in `ouro-check.json`: for a page, as the check names it, each state's name and the controls to press in turn to reach it, as Playwright selectors. The check presses its way to each state and checks it as a page of its own, named after the page and the state.[^check-states] A press that finds nothing to press makes the state a page that did not load. As with `press`, list presses that only change what the page shows, and point the check at made-up data.

```json
{
  "states": {
    "/?mock=1": { "a chat open": ["text=Launch planning"], "the calendar": ["role=button[name=Calendar]"] }
  }
}
```

Each page and state loads afresh in a browser context of its own, so what one saves (an app's last view) reaches no other, a route in its address's hash included; and its finite animations run to their end, up to 2 s, before the rules judge it.[^check-settle]

`first-content` is measured again on a second load when its first load is over budget. It is reported only when both loads are over, at the lower of the two, so one slow load on a busy runner fails no gate.[^check-first-content] `layout-shift` reads one load of each page at each size, and `inp` a few presses, so a result just over its budget can be the runner rather than the page.[^check-measured] Check a borderline `layout-shift` or `inp` finding before you fix it: run the check on that page again, or raise `pressRepeat`. A finding well over its budget, or one that shows at several sizes, is the page.[^check-measured]

A new rule can start without failing a build: waive it on all pages, with the reason, and remove the waiver once its findings are fixed.[^check-shard] When an Ouro Current update brings in a rule, it records the findings the app already has for it in `ouro-check.json`'s `known`, by what each says up to the token to use: they are reported and pass, and a new finding of that rule fails.[^check-known] Move them onto the theme in a pull request of their own, and remove each from `known` as it goes. This repository's own site does that while its off-scale rule settles.[^check-site]

Add it, build your app, run it on the built folder (or on URLs), and fix what it reports:

```sh
npx shadcn@latest add ourostack/ouro-ui/ouro-check#v1.3.654
node scripts/ouro/check/check.ts dist
```

`ouro-check` installs under `scripts/ouro/check/`, outside your TypeScript project, with the [Ouro AX](ax.md) files it runs on in your lib folder (`src/lib/ouro/ax/` in an app with `src/`), and names `playwright` and `axe-core` as devDependencies, without a version.[^kit-versions] It runs in Node, so it imports Node's modules, which a Vite app's `tsconfig.app.json` leaves out (`"types": ["vite/client"]`); outside `src/`, `tsc -b` never reads them.[^check-vite] It imports the kit as `#ouro-ax/<file>`, which package.json names once, with `src/lib` replaced by your lib folder (what `components.json`'s lib alias points at):

```sh
npm pkg set "imports.#ouro-ax/*=./src/lib/ouro/ax/*"
```

Without that line the check still finds the kit from `components.json`; the other tools need it.[^check-resolve]

It writes `ouro-check/report.json`, `summary.md`, a contact sheet of every size a page was checked at in `sheets/`, and a captioned close-up of each finding in `findings/`, at most 40 a page.[^check-many] Its exit code is the one every Ouro tool gives, from the Ouro AX kit's table, so it can gate CI:[^check-exit]

| Exit | Meaning |
| --- | --- |
| `0` | Nothing found that `ouro-check.json` does not waive. |
| `1` | An error: the check itself stopped before it finished, as when the browser would not start. It prints why. |
| `2` | A usage problem, such as a folder that does not exist. |
| `3` | Findings to fix: the summary lists them. |



- `--pages "docs/**"` checks only the pages a glob matches; `--sizes 390x844,1440x900` and `--themes light` narrow the sweep.
- `--shard 1/4` checks the first of four shares, and `node scripts/ouro/check/check.ts merge <out folders>…` joins the shares' folders into one report, the same as one run's.[^check-shard]
- `--before <earlier report.json>` adds a captioned before and after for each finding gone since.[^check-before]
- A page that draws after it loads says when it is ready: it fires `ouro:ready` (or an event you name with `--ready-event`), or sets `data-app-ready`. The check waits up to 15 seconds, then checks the page as it is.[^check-ready]

To keep a finding on purpose, other than `blurry-image`, mark the element with `data-ouro-allow="<rule>"` and a reason in `data-ouro-allow-why`; an allow without a reason does not count.[^check-allow] Every opt-out with its reason goes into `report.json`, under `allowances`.[^check-allowances] It also records what it scanned, under `scanned`: the pages, sizes and themes swept, the visits made, how many of them reached first content, and the elements and rule checks they read, so a report with no findings can be told from a run that reached nothing, and a page that never drew is counted, not left out.[^check-scanned]

If your app's own rules keep `data-ouro-*` for Ouro's components, use the plain aliases instead. They are part of the check's interface and are not deprecated. Each takes its reason as its value, and like `data-ouro-allow`, it counts only with one; a reason of spaces is none:[^check-aliases]

| Alias | Opts out of |
| --- | --- |
| `data-overlap-ignore="<reason>"` | `overlap` |
| `data-long-lines-ok="<reason>"` | `long-lines` |
| `data-clip-ok="<reason>"` | `clipped-text` |
| `data-scroll-x="<reason>"` | `sideways-scroll` |
| `data-size-ignore="<reason>"` | `sideways-scroll`, `clipped-text`, `long-lines` and `stretched-image`; a broken picture is broken at any size and no reason makes a blurry one sharp, so each is still a finding[^check-aliases][^check-blurry-unwaivable] |
| `data-image-fade-ok="<reason>"` | `image-fade`, on the picture, a box around it or the overlay[^check-image-fade-allow] |

An element that still sticks out past the screen makes the page scroll sideways, so give its content a scroller of its own (`overflow-x: auto`); the alias stops the rule naming the element, not the page.[^check-allow] To waive a rule on whole pages, list it in `ouro-check.json`, with the reason:

```json
{ "waive": { "docs/legacy/**": { "long-lines": "Imported articles keep their layout until they are rewritten." } } }
```

### A blurry picture can't be waived

A picture drawn larger than its pixels looks soft on the screens that show it, whatever the reason, so `blurry-image` has no opt-out.[^check-blurry-unwaivable] `data-ouro-allow="blurry-image"` is itself a finding, which names the element and still reports the picture, and neither `data-size-ignore` nor a `"*"` or `all` allow covers it.[^check-blurry-unwaivable] A waiver in `ouro-check.json` that names `blurry-image` is a usage problem: the check exits 2 before it opens a page.[^check-blurry-config] Give the picture a larger source, or a srcset whose largest file covers its drawn width at 2x.

`--images-report <file.json>` writes each blurry picture once a page, with what a tool needs to replace it: the page, a selector, the file it drew (`currentSrc`), that file's pixels, its widest drawn width, the density and the width it needs, the sizes it was found at and, when the check served a built folder, the file on disk.[^check-images-report] `merge --images-report` writes the same from the shares.[^check-images-report]

```sh
node scripts/ouro/check/check.ts dist --images-report images-report.json
```

### Long lines are opt-in

How long a line of text may run is a design choice, so the check assumes no measure and never asks you to cap text width.[^check-measure] `long-lines` runs only where `ouro-check.json` declares the measure your design or the request already sets.[^check-measure] Every other rule runs by default.[^check-rules]

```json
{ "measure": { "**": "100 chars", "main .chat-message": "800px" } }
```

- A key that starts with `/`, such as `/docs/**`, or one made only of `*`, is a page glob; it holds the prose on the pages it matches: `p`, `li`, `dd`, `blockquote`, `figcaption` and `[data-prose]`. `"**"` matches every page.[^check-measure] Any other key is a CSS selector, which may hold a `/` of its own, and it holds exactly the elements it matches on every page, a container of paragraphs included.[^check-measure] An element two keys hold is checked against the first.[^check-measure]
- A measure is `px` (how wide a rendered line may be), `ch` (the width of that many zeros in the element's own font) or `chars`. `"100 chars"` counts the characters a rendered line holds on average, as the rule always has, so it is met by how the text is composed, not by capping its CSS width.[^check-chars]
- A measure that is none of these, or a selector the browser cannot read, makes the check exit `2`.[^check-exit]

### Let text use the width its column gives it

Don't cap prose with a reading measure (`max-width: 65ch`, `max-w-prose`, `46rem`) unless your design sets one. Such a cap, inside a column much wider than it, leaves half the page empty beside the text, so `narrow-text` reports it: the element, the rule that set the cap and the width the column offers.[^check-narrow-text] Let the text use the width it has. If the design really sets a measure, declare it, and the rule leaves the text it covers alone: read the cap from a `--measure-*` token (`max-width: var(--measure-lede)`, or Tailwind's `max-w-(--measure-lede)`), put `data-ouro-measure` on the text or around it, or declare it in `ouro-check.json` (`measure`).[^check-narrow-text] A measure declared in the page passes at 40ch or wider in the text's own font, and is reported narrower, as too narrow to read comfortably; a cap on a box that holds more than prose is the page's layout, and passes.[^check-narrow-measure]

### Pictures end on a hard edge

End a picture on a hard edge, or put it on a solid band. Don't fade it into the page, or into nothing, at any edge, by a mask, an overlay or a pseudo-element's wash. Keep light painted into the picture itself, and gradients that are not over a picture, such as a painted sky band or a skeleton's shimmer. The screen check's `image-fade` rule finds a fade the browser draws. `fades.ts`, which `ouro-check` installs beside `check.ts`, finds one in the source before anything is built: every gradient used as a mask in a stylesheet, a style attribute, a Tailwind class (an arbitrary `mask-image` property or `mask` value, or one of Tailwind's gradient mask utilities) or a style object.[^fades] It finds a wash too: a gradient that reaches transparent on a layer over a picture, a `::before` or `::after` or an absolutely positioned or fixed box other than a hairline, in a file that draws an `<img>`, `<picture>`, `<video>` or `url()` picture (not a font's, a stylesheet's or a cursor's), or a gradient named a wash, scrim, fade, veil or haze. A sky band or a glow with no such role passes.[^fades-wash]

```sh
node scripts/ouro/check/fades.ts src
```

It reads `.css`, `.scss`, `.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`, `.astro`, `.html`, `.svelte` and `.vue` files, skipping `node_modules`, build output (`dist`, `build`, `storybook-static`, `coverage`) and hidden folders.[^fades-files] Each finding gives the file, the line, the declaration and the fix, and it exits 3 when there is one, 0 when there is none and 2 on a usage problem, as `check.ts` does.[^fades-exit] A mask or a wash that fades text or controls rather than a picture, such as a row that scrolls sideways or a folded paragraph, stays when its line, or the comment just above it, says why, `fade-ok: <reason>`; a wash in a rule may say so at the rule's start too, and a marker without a reason does not count.[^fades-ok] Ouro HX's own such masks (Tabs' overflow, Collapsible's fold and the scroll fade) carry one, and this repository's CI runs `fades.ts` over `registry/` and `site/` in the required `ci` check.[^fades-ci]

### Pictures at the widths a screen needs

A `blurry-image` finding means the screen draws a picture larger than its file. `ouro-images` writes each raster picture in a folder as AVIF and WebP at each of 320, 640, 960, 1280, 1920, 2560, 3840 and 5120 pixels wide that is narrower than the picture, and at its own width, with `images.json` listing the srcset of each.[^images] `images.json` records what each picture's files were made from, its bytes and the options, so a second run writes only what changed, and a new `--quality` writes them all again.[^images-kept] It turns a photo upright as its EXIF orientation says, and leaves out an animated picture, which would lose its frames; serve that one as it is.[^images-upright]

```sh
npx shadcn@latest add ourostack/ouro-ui/ouro-images#v1.3.654
node scripts/ouro/images/images.ts pictures --out public/images --base /images/
```

Then draw each picture from the manifest, and the browser takes the smallest file that is sharp on its screen:

```tsx
import images from "../public/images/images.json";

const hero = images["hero.png"];

<picture>
  {hero.sources.map((source) => <source key={source.type} type={source.type} srcSet={source.srcset} sizes="100vw" />)}
  <img src={hero.src} width={hero.width} height={hero.height} alt="The team at the launch" />
</picture>;
```

It refuses a picture too small to be drawn sharp, names it and why, writes nothing for it and exits 1, while it writes the rest: with `--max-width <px>`, the widest the pictures are drawn in CSS pixels, a picture narrower than twice that, and with `--min-long-edge <px>` one whose long edge is shorter.[^images-refuse] A picture in a folder named `hero`, `heroes`, `scene` or `scenes` needs a long edge of 2048 or more whatever the options say.[^images-refuse]

`ouro-images` installs `scripts/ouro/images/images.ts`, outside your TypeScript project, with the [Ouro AX](ax.md) files it runs on in `lib/ouro/ax/`, imported as `#ouro-ax/<file>` (the imports line in [the screen check](#the-screen-check) names that folder), and names `sharp` as a devDependency.

### Cover a state nobody has designed yet

Put `data-ouro-veil` on the element a state isn't designed for (the whole app below its narrowest designed width, a panel whose states are still open), and `ouro-base` covers it with a solid "Not designed yet" layer, dashed and plain, so no one takes it for the design. The value is the reason: `data-ouro-veil="below 600px"` reads "Not designed yet: below 600px". Ouro check leaves every finding inside the veil alone.[^check-veil] The veil is only the cover: the app sets and removes the attribute itself (a media query's class, a flag) and puts `inert` on the veiled content so a keyboard can't reach what is under it.

### Keep a decision as a check

When a person decides something about the design while you iterate ("people use the squircle", "the toolbar holds only window-wide actions", "one label per place"), write it into `ouro-check.json` as a `decisions` entry instead of a test file. It runs with the rest of Ouro check, so the decision keeps holding.[^check-decision]

```json
{
  "decisions": [
    { "name": "people use the squircle", "selector": "[data-person]", "expect": { "border-radius": { "not": "50%" } } },
    { "name": "the toolbar holds only window-wide actions", "selector": "[data-toolbar] > *", "only": "[data-window-action]" },
    { "name": "one label per place", "selector": ".label", "within": ".place", "count": { "max": 1 }, "width": { "min": 640 } }
  ]
}
```

Each entry has a `name` (the person's words, which head the finding), a `selector`, and at least one of `expect`, `count` or `only`.[^check-decision] `pages` (a page glob) and `width` (`{ "min", "max" }`) say where it holds; without them it holds on every page at every width.[^check-decision]

- `expect` maps a computed style property (`border-radius`) or a box measure (`@width`, `@height`, `@x`, `@y`, `@right`, `@bottom`, in pixels) to a text it must equal, a number it must equal within half a pixel, or `{ "min", "max", "not", "match" }`, where `match` is a regular expression's source.
- `count` is how many drawn matches there may be (a number, or `{ "min", "max" }`); with `within`, a selector, it is counted in each matching box.[^check-decision]
- `only` means each drawn match must also match this selector.[^check-decision]

Only drawn elements outside a veil count. A selector the browser refuses is reported as a finding, and a malformed entry stops the run with the fix.

### Watch it while you iterate

`ouro-check watch <url> --watch src` reruns the fast rules and your `decisions` against a running dev server, headless, and prints only what changed: findings a run opened (`+`) and findings it closed (`-`), or `· no change`.[^check-watch] It checks one screen size (1280x800) in light, with no axe and no measured rules, and keeps its pictures in a scratch folder it removes, so a run takes seconds and the person's browser is never touched.[^check-watch]

- `--watch <folder,…>` reruns when a file under a folder changes (after it has been quiet for 300 ms); `--every <seconds>` (default 5) reruns after that many seconds even when nothing changed, so a change in a place no folder names still shows up.[^check-watch]
- `--sizes`, `--themes`, `--pages` and `--ready-event` take what they take in a full check; `--times <n>` stops after n runs, so a script can use the final exit code (3 while findings are open).[^check-watch]
- Start it on a second dev server that no person has open, so the check never drives the view they watch.

### Hand off to a person

Run `ouro check --handoff` and it writes `handoff.md` beside `summary.md`: the floor it proves, what it can't judge (whether someone finishes the task unaided, whether the words mean to them what you meant, whether they trust the screen, whether it works on their own device) and the sessions to run next.[^handoff] Declare the sessions in `ouro-check.json`, one per task, with the question that tells whether the person got there and what to watch for:

```json
{ "usability": [{ "task": "Book an appointment for next Tuesday", "outcome": "What appointment do you have now?", "observe": "Where they hesitate before the confirm button", "page": "/book" }] }
```

Fix the findings that fail first, so a session is spent on the task and not on a broken screen. A clean check leaves those questions open.

## How a list feels

[Ouro Feel](https://github.com/ourostack/ouro-ui/blob/main/feel/README.md) measures how a scrolling list feels while real input moves it: the reader's row jumping, blank frames, late frames and how long a wheel waits to move it. Its probe is `ouro-feel-probe`, one plain script the page runs first, before its own scripts.[^feel-probe]

```sh
npx shadcn@latest add ourostack/ouro-ui/ouro-feel-probe#v1.3.654
```

It installs `scripts/ouro/feel/ouro-feel-probe.js`. Put it first in the page's `<head>`, or inject it into your web view before the page loads, then call `window.ouroFeel.watch` from your own cases and `window.ouroFeel.stop` for the counts.

## The first-run harness

Ouro check reads pages. A first run also needs a scripted session against the installed app, from a fresh machine, where the person dismisses the dialogs, presses controls early, quits, goes offline and signs out, and the app must still end signed in and synced, or offer one obvious way forward.[^first-run-detours] Ouro check ships that harness for a Mac app beside the check, in `scripts/ouro/check/first-run.ts`.[^first-run-session] It reads what a person reads, so the shipped build needs no test hooks: the system's accessibility tree, through `first-run-ax-tree.swift` (built with `swiftc` on the run's Mac), and the screen's pixels.[^first-run-eyes]

| Part | What it does |
| --- | --- |
| `FirstRunSession` | Drives the path to signed in and synced (`toGoal`), judges every look, pushes each dialog away (`probe`), judges what an action left (`judgeAfter`), checks a signed-out app (`stranded`: each space, the menu bar item, the account button, pressed once a window still starting has drawn it), runs a detour (`run`), and writes `gate/gate.json` with a picture and a tree of each state and each failure (`finish`, which is false when any step failed or the watch saw a violation).[^first-run-session] |
| The judges | No blank pane, no dead end, no dismissable required step and no signed-out empty state, on an accessibility tree, with fixed limits: blank 5 s, dead end 10 s, a signed-out empty state 2.5 s, progress with no way forward 90 s.[^first-run-limits] |
| `DETOURS` | What a person does off the path, as data an app extends: every dialog dismissed by Escape, its close button or a click outside; every control pressed before sign-in; quit, or close and reopen, at each step; No to every question; the sign-in cancelled; permissions denied; started offline.[^first-run-detours] |
| `leftovers`, `reset` | What a Mac still holds of the app (its bundle, data folders, keychain items, a login item turned on): none on a fresh CI runner.[^first-run-machine] |
| `unreachable`, `offline` | The app's sign-in, its sync or everything it reaches refused (or left hanging) with `pf`, then lifted; it needs `sudo -n pfctl`, as a CI runner has.[^first-run-network] |

An app passes its own words, steps, sign-in and controls; nothing in the harness names an app:

```ts
import { buildEyes, DETOURS, Eyes, FirstRunSession, leftovers, type AppConfig, type Report } from "./scripts/ouro/check/first-run.ts";

const eyes = new Eyes(buildEyes(".tmp/ax-tree"));
const app: AppConfig = {
  vocabulary: { forward: /^(Sign in|Next|Retry|Continue)\b/, progress: /…$|^(Loading|Signing in)/, emptyWhileSignedIn: /Nothing new|No messages yet/, close: /^(Close|×)$/ },
  bundle: "/Applications/Example Mail.app",
  processName: "Example Mail",
  // …its pid, signedIn, synced, checkpoint, advance (signing in as the test tenant's account, never a person's),
  // open, quit, activate, controls, spaces, accountButton, menuBarItem and signInNetwork
};
assert.deepEqual(leftovers({ bundle: app.bundle, id: "com.example.mail" }), []); // a fresh machine
const report: Report = { step: (name, ok, evidence) => results.push({ name, ok, evidence }), note: () => {}, log: console.error, at: clock };
const session = new FirstRunSession({ out: ".tmp/first-run", eyes, app, report });
await session.run(DETOURS.find((d) => d.id === process.env.DETOUR)!); // one detour per fresh VM
assert.ok(session.finish(process.env.DETOUR!));
```

An app's own detour is one more entry: `[...DETOURS, { id: "switch-account", title: "a second account added during the welcome", at: (cp) => cp === "welcome", run: async (s) => { … } }]`. Each finding names the rule, the state, how long and from when: `dismiss-escape-1: Escape on "Welcome, Ada": escape took "Welcome, Ada" away, and what it left fails: …`.[^first-run-dismiss]

### On Windows

The same harness runs a Windows app's first run, unchanged, through `first-run-windows.ts`. `buildWindowsEyes` builds the eyes from `first-run-uia-tree.cs` with the .NET Framework's own `csc`, which every Windows has; they read the app through UI Automation and give each element the role the judges read.[^first-run-windows-eyes] `windowsSystem` is the machine the session takes, and it answers each macOS command the harness asks the way Windows does:[^first-run-windows]

| The harness asks | Windows answers |
| --- | --- |
| `screencapture` | the eyes' one-shot picture |
| `open` | the app's own `open`, else the shell's `start` on the shortcut or program |
| `pgrep`, `pkill` | the app's own, else the processes with that image name, or whose command line holds the pattern |
| `curl`, `dscacheutil` | `curl.exe`, and `Resolve-DnsName` |
| `sudo -n pfctl` | Windows Firewall's outbound block rules named `ouro-first-run`. Each profile that was off is turned on for the hold, then put back off with its own default actions; a profile that was on is left alone.[^first-run-windows-firewall] Windows refuses at once, so a `hang` hold refuses too.[^first-run-windows-firewall] |
| `sudo -n sfltool dumpbtm` | the Run keys and the Startup folder, as login items[^first-run-windows-login] |

The runner must be an administrator, as a GitHub-hosted Windows runner is, so the firewall takes the rules. `windowsDataPaths` names what Windows keeps beyond a Mac's Library, the app data folders and the Start menu shortcut, for `leftovers`. The eyes find the app's notification-area icon (Windows' menu bar item) by the name `extra-menu` gives, else `OURO_TRAY_NAME`, else the app's window title.

```ts
import { buildWindowsEyes, DETOURS, Eyes, FirstRunSession, leftovers, windowsDataPaths, windowsSystem, type AppConfig } from "./scripts/ouro/check/first-run.ts";

const exe = buildWindowsEyes(".tmp/uia-tree.exe");
const sys = windowsSystem({ eyes: exe, pgrep: (name) => (name === "Example" ? examplePids() : []) });
assert.deepEqual(leftovers({ bundle: installDir, id: "Example", extraPaths: windowsDataPaths({ folder: "Vendor\\Example", shortcut: "Example" }) }, { sys }), []);
const app: AppConfig = { bundle: shortcut /* what open opens */, processName: "Example", menuBarItem: 0 /* its notification-area icon */ /* , … */ };
const session = new FirstRunSession({ out: ".tmp/first-run", eyes: new Eyes(exe, sys), app, report, system: sys });
```

A control's shortcut reads the same on both, since the eyes send Ctrl where a Mac's is ⌘.[^first-run-windows-keys] CI's First run on Windows workflow proves it on a fresh `windows-latest` runner: it drives a page opened in Edge as an app through the `dismiss-escape` detour, which must pass, and again with the page left blank once its welcome dialog goes, which must fail on that dismissal.[^first-run-windows-proof]

### A managed Mac

On a Mac its organization manages, an Enterprise SSO extension can take the identity provider's sign-in from the app's web view, and it keeps the silent sign-in (`prompt=none`), which an app runs in a web view no one sees, waiting until a web view is in a window.[^first-run-sso-webkit] An app that waits for it shows the person nothing to do until it gives up. `first-run-sso.ts` plays that extension on a runner the harness owns, beside `first-run-network.ts`'s holds: its stand-in takes the identity provider's hosts (pointed at it in `/etc/hosts`, its certificate authority trusted for the run), holds each request that matches `hold` unanswered, passes every other request to the real host, and leaves a client whose TLS hello offers no ALPN, an app's own network stack, untouched.[^first-run-sso-stand-in] Lifting it puts `/etc/hosts` back, takes its authority out of the System keychain, so the system trusts it no more, and deletes its keys.[^first-run-sso-lift]

`managedMac` is the detour. It holds the silent sign-in for the whole path, so the app calls its `end` once the session's path is over, in a `finally`, so a run that throws still puts the Mac back: `end` lifts the hold and judges what the stand-in saw.[^first-run-sso-detour] The judge fails a run where the app never asks for the sign-in page in the open after the first held request, or asks later than `giveWayMs` (20 s by default), and a run that held nothing.[^first-run-sso-judge]

```ts
import { FirstRunSession, managedMac } from "./scripts/ouro/check/first-run.ts";

const detour = managedMac({ hosts: ["login.microsoftonline.com"], hold: { path: "/oauth2/v2\\.0/authorize$", params: { prompt: "none" } }, dir: ".tmp/sso" });
try {
  await session.run(detour);
} finally {
  detour.end(session); // lifts the hold even when the run throws
}
assert.ok(session.finish(detour.id));
```

It needs `sudo -n`, as a GitHub-hosted Mac has, and one difference stays: WebKit gives up on a request the stand-in holds after the request's own time limit, where the extension waits for as long as it takes. CI's First run on a managed Mac workflow proves it on a fresh `macos-latest` runner: Apple's networking meets the hold, the same path in the open passes, curl with no ALPN is never seen, and lifting it puts the Mac back.[^first-run-sso-proof]
