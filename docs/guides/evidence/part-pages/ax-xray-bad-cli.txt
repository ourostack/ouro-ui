## What fails, and the fix

### `cli.no-dev-commands`: No message the CLI gives an agent or a person (help, a refusal, an error, a next step, an outcome's `human.resume`, a doctor's fix) asks for a developer command, a repository path or a step that only works in a source checkout, unless the step is marked `sourceCheckout: true`.

Why: An agent passes a next step on to the person, who has the installed tool and no source checkout, so a repository script fails for them and leaves both stuck.

Fix: Name the command the installed tool runs (`<cli> <command>`) or the step to take by hand. A step that only works in a source checkout gets `sourceCheckout: true` (a next step, a doctor's fix), and only a source checkout shows it.

- **pnpm build**: `bad-cli help --json` commands[2].summary: "Checks the setup; run `pnpm build` first" asks for `pnpm build`
- **pnpm dev**: `bad-cli edit` prints: "Start the dev server with pnpm dev." asks for `pnpm dev`
- **node scripts/doctor.mjs --fix**: `bad-cli doctor --json` rows[0].fix.command: "node scripts/doctor.mjs --fix" asks for `node scripts/doctor.mjs --fix`
- **npm run writes -- on**: `bad-cli doctor` prints: "Writes are off: run npm run writes -- on." asks for `npm run writes -- on`

### `cli.unknown-flag`: An unknown flag fails before anything runs, and the error names the flag.

Why: A silently ignored flag gives an agent a wrong answer that looks right: `--limt 2` returns everything.

Fix: Check every flag against the command's declared flags before acting; refuse an unknown one with the usage exit code.

- **rooms**: `bad-cli rooms --ax-xray-no-such-flag --json` → exit 0; stdout: {"rooms":[{"ref":"r1"}]}: the flag was ignored
- **rooms --limt**: `bad-cli rooms --limt 2 --json` → exit 0; stdout: {"rooms":[{"ref":"r1"}]}: --limt was ignored, so the answer is not what was asked
- **doctor**: `bad-cli doctor --ax-xray-no-such-flag --json` → exit 1; stdout: {"ax":"checks/1","verdict":"failed","summary":"1 of 1 check failed: The cache. 0 passed, in under 0.1s.","durationMs":5…

### `cli.ambiguous-verbs`: Ambiguous verbs (edit, delete, remove) don't act; they answer with the specific commands.

Why: `edit` could mean a private draft or a message others already saw; guessing is how agents do the wrong thing.

Fix: Answer each ambiguous verb with one line naming the private command and the one others see.

- **edit**: `bad-cli edit` → exit 0; stderr: Start the dev server with pnpm dev.
- **delete**: `bad-cli delete` → exit 1; stderr: what?
- **remove**: `bad-cli remove` → exit 1; stderr: what?

### `cli.exit-codes`: Exit codes are documented, and every exit code the CLI gives is one of them.

Why: Stable, documented exit codes let an agent branch without parsing prose.

Fix: Keep one exit-code table, print it in help and help JSON, and exit only with codes from it.

- **help**: no exit codes in help --json or an `Exit codes:` line

### `copy.precise-failure`: Every failure the CLI reports to an agent or a person (a refusal, an error, an outcome's `error` and `summary`, `human.reason`, a doctor's finding, and any failure `help --json` describes) says what happened and precisely why (the system and its answer), who or what caused it where that is known, and the next step; when the cause is unknown, what was tried and what came back. It never stops at "couldn't", "could not", "something went wrong", "unable to", "failed to load", "an error occurred" or a bare "Error" or "Failed": a phrase passes only with its cause after it in the same sentence ("Couldn't send: you're offline", "… because the server refused it"; not "Couldn't send: try again").

Why: A vague failure gives the agent nothing to pass on and nothing to act on: it can't tell the person whether to retry, ask someone or change something, so both are stuck.

Fix: Name the system and its answer ("The mail service says this file was deleted"), who or what caused it, and the next step as a command or an action ("Ask its owner to share it again"). When a precise text still holds a phrase ("The card service says your card could not be charged. Use another card."), list it in `--failure-copy-allow` with its reason.

- **Could not reach the room service. Try later.**: `bad-cli help --json` commands[0].errors[0]: "Could not reach the room service. Try later." says "could not" and not what happened or why

### `cli.error-teaches`: Every error names a next action: a command to run or a flag to add.

Why: An agent recovers from the error alone when the error says what to do instead.

Fix: End each error with what to do: `Try "<cli> conversations"`.

- **ax-xray-no-such-command**: `bad-cli ax-xray-no-such-command` → exit 1; stderr: what?: names no command or flag to try
- **delete**: `bad-cli delete` → exit 1; stderr: what?: names no command or flag to try
- **remove**: `bad-cli remove` → exit 1; stderr: what?: names no command or flag to try
- **doctor --ax-xray-no-such-flag**: `bad-cli doctor --ax-xray-no-such-flag --json` → exit 1; stdout: {"ax":"checks/1","verdict":"failed","summary":"1 of 1 check failed: The cache. 0 passed, in under 0.1s.","durationMs":5…: names no command or flag to try

### `cli.plain-pipe`: Output into a pipe is plain text: no ANSI escape codes and no carriage-return redraws, and `NO_COLOR` wins over `FORCE_COLOR`.

Why: An agent reads a pipe. Escape codes and redraws are noise in its context and break a match on the text.

Fix: Decide colour and progress from the stream: colour and redraws only on a terminal, and `NO_COLOR` always off (`terminalStyle` and `createProgress` in ax-terminal).

- **bad-cli edit**: a carriage return redraws piped output
- **bad-cli doctor**: escape codes in piped output: "\u001b[35mDOCTOR\u001b[0m"
- **NO_COLOR=1 FORCE_COLOR=1 bad-cli --help**: escape codes in piped output: "\u001b[1mbad\u001b[0m"

### `cli.read-json`: Every read takes `--json` and prints exactly one JSON document (a stream prints JSON lines) and writes nothing to stderr. It exits 0, except a check command (a doctor), which exits with the declared `findings` code when its checks find a problem.

Why: One parseable answer per call is the cheapest thing for an agent to consume.

Fix: Give the read a `--json` that prints the same data the text shows, as one document.

- **rooms**: `bad-cli rooms --json` → exit 0; stdout: {"rooms":[{"ref":"r1"}]}; stdout is not one JSON document
- **doctor**: `bad-cli doctor --json` → exit 1; stdout: {"ax":"checks/1","verdict":"failed","summary":"1 of 1 check failed: The cache. 0 passed, in under 0.1s.","durationMs":5…

### `cli.help-width`: No help line is wider than the width limit (100 columns by default).

Why: Long lines wrap unpredictably in terminals and transcripts and cost tokens to re-read.

Fix: Wrap help at one width in the help renderer, not by hand.

- **--help**: 1 lines over 100 columns, first:   rooms   List rooms, and also this line goes on and on well past any sensible terminal width so it wraps badly everywhere.

### `cli.unknown-command`: An unknown command fails with the usage exit code and lists the commands, or names the help that lists them.

Why: A guessed command is the commonest first call; the error should be the menu.

Fix: On an unknown command, print one line: `unknown command "x". Commands: a, b, c. Details: <cli> help`, and exit with the usage code.

- **ax-xray-no-such-command**: `bad-cli ax-xray-no-such-command` → exit 1; stderr: what?; lists 0 of 3 commands

### `cli.flag-suggest`: A misspelt flag's error names the closest real flag.

Why: The error should carry the fix, so the next call is right.

Fix: Suggest the declared flag nearest by edit distance: `unknown flag --limt; did you mean --limit?`.

- **rooms --limt**: `bad-cli rooms --limt 2 --json` → exit 0; stdout: {"rooms":[{"ref":"r1"}]}; does not name --limit

### `cli.one-line-error`: Every error is one line on stderr; stdout stays empty, or with `--json` holds the same error as one JSON document. A command that help JSON marks `protocol: true` may print its one JSON reply line on stdout instead, since another program reads it.

Why: One line is cheap to read and easy to quote back; stdout stays parseable.

Fix: Catch errors at the entry point and print one line to stderr.

- **doctor --ax-xray-no-such-flag**: `bad-cli doctor --ax-xray-no-such-flag --json` → exit 1; stdout: {"ax":"checks/1","verdict":"failed","summary":"1 of 1 check failed: The cache. 0 passed, in under 0.1s.","durationMs":5… (0 stderr lines, 1 stdout lines)

### `cli.check-verdict`: A check command (a doctor) puts its verdict on the first line of its text, and its `--json` has the same verdict and exit code.

Why: A person reads the first line and an agent reads the JSON: they must agree, and neither should scroll for the answer.

Fix: Declare the checks with `defineChecks` (ax-checks) and print the report with `checksText` or `printChecks`, or return it from a kit command.

- **doctor**: `bad-cli doctor` starts "DOCTOR", not the verdict "1 of 1 check failed: The cache. 0 passed, in under 0.1s."
