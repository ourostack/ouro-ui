# Avatar's style cost in a Command palette's rows, before and after Avatar drew its initials from its surface and
# read its colours from ouro-base's --ouro-avatar-tint-* and --ouro-avatar-ink-* tokens
#
# Source: avatar-style-cost.probe.tsx.txt beside this file, copied to test/style-cost.probe.test.tsx and run with
# `pnpm exec vitest run --project ouro-chromium test/style-cost.probe.test.tsx` (and ouro-webkit) on a MacBook Pro,
# macOS, Playwright's Chromium and WebKit. A Command palette is open with 600 rows, each a person with an extra-small
# Avatar of initials (avatar rows) or a plain svg icon (icon rows, the baseline). One timing: the listbox goes to
# display: none, its style is read, it is shown again, and getComputedStyle on its last row is timed, which styles the
# listbox's rows again. Each run is the median of 31 timings after 3 to warm up. Each engine ran three rounds, main and
# this change taking turns, each in light and in dark: six runs a side. WebKit's timer counts whole milliseconds.
# Safari 16.4 and later support margin-trim, so Tailwind's fallback for engines without @property never applies there;
# Playwright's WebKit lacks margin-trim and applies it, setting Tailwind's custom properties on every element and
# ::before. The probe's VITE_NOFALLBACK=1 deletes that @supports block from the page's stylesheets to read what Safari pays.
