# Changes in this release

- Ouro AX: a positional word outside its arg's values is refused with the usage exit code and a fix that names the closest value, as an enum flag is.
- Changed: web vendors [core v0.18.3](test/fixtures/a2ui/core.json "verify:equals(test/fixtures/a2ui/core.json#coreTag)=v0.18.3"), whose tree validator refuses a confirm sheet that shows the person one value and sends another ([ourostack/ouro-ui-core#88](https://github.com/ourostack/ouro-ui-core/issues/88 "verify:urlOk(https://github.com/ourostack/ouro-ui-core/issues/88)")). It also refuses a button input the catalog's action doesn't declare, and an app's `label` resolver now names only id fields, those whose catalog input has `shownAs`: give an id field `shownAs` to keep its name on the confirm sheet. A name the agent chooses is the catalog's only when the catalog itself has it, and a data-model pointer never reaches an object's prototype ([ourostack/ouro-ui-core#91](https://github.com/ourostack/ouro-ui-core/issues/91 "verify:urlOk(https://github.com/ourostack/ouro-ui-core/issues/91)")).
- Fixed: Ouro Feel's probe [asks for no frames while nothing is watched](scripts/feel.test.mjs "verify:testExists(scripts/feel.test.mjs::Ouro Feel's probe asks for no frames while it watches nothing and nothing waits on a paint, so a page with it loaded idles as without it)"), so a page with it loaded idles as without it, and [waits a second before polling again when an app's probe service answers at once with no command](scripts/feel.test.mjs "verify:testExists(scripts/feel.test.mjs::Ouro Feel's probe waits before polling again when its bridge answers at once with no command)"), where it used to poll without pause; [watching a scroll adds no layout a frame and under half a millisecond of script](scripts/feel.test.mjs "verify:testExists(scripts/feel.test.mjs::Ouro Feel's probe, watching a scroll, adds no layout a frame and under half a millisecond of script)"), which a test now holds it to.
- New: Ouro Feel's `watch` [takes the list as a selector and finds it again each frame](scripts/feel.test.mjs "verify:testExists(scripts/feel.test.mjs::Ouro Feel's probe takes the list as a selector and finds it again each frame, so a list put in another's place is measured)"), so an app that opens another conversation in a new list is measured in the new one: `ouroFeel.watch({ scroller: "[data-ouro-message-list-scroller]", … })`.
- New: [MessageList `estimatedItemHeight`](registry/ouro/components/ouro/message/message-list.windowing.test.tsx "verify:testExists(registry/ouro/components/ouro/message/message-list.windowing.test.tsx::MessageList windowing > draws only the rows that fill the view in the first commit, given their estimatedItemHeight, where the built-in estimate would draw more)"), the usual height in pixels of a row the list has not measured yet, for an app whose rows are much shorter or taller than the built-in 96 (`<MessageList estimatedItemHeight={130}>`), so a list opens drawing only the rows that fill its view; `estimateSize`, `itemHeight` and `defaultItemHeight` name it in a type error and a development message.
- Changed: [a `heightCache` also keeps the height the list took for a row not measured yet](registry/ouro/components/ouro/message/message-list.windowing.test.tsx "verify:testExists(registry/ouro/components/ouro/message/message-list.windowing.test.tsx::MessageList windowing > opens with the estimate a heightCache kept from the list before it, for the rows neither measured)"), so a list handed it opens with that estimate instead of 96 when it is given no `estimatedItemHeight`.
- Fixed: [a MessageList whose reader turns the wheel up to the top faster than the rows above came in no longer jumps](registry/ouro/components/ouro/message/message-list.windowing.test.tsx "verify:testExists(registry/ouro/components/ouro/message/message-list.windowing.test.tsx::MessageList windowing > holds the reader's row to the pixel as a wheel takes them past the top before the shorter rows above were paid, keeping the rest as space above the first message)") when those rows are shorter than the space kept for them: what the top stops stays as space above the first message, and goes, moving nothing, once the reader scrolls past it with the wheel at rest.
