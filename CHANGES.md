# Changes in this release

- `Celebrate` takes `cap`, one limit or several, such as once per conversation and three times a day, counted under `capKey` or each limit's `key` in the same store as `Moment`'s cap; past a cap the message shows and is heard with no confetti ([test](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/components/ouro/celebrate/celebrate.test.tsx "verify:testExists(registry/ouro/components/ouro/celebrate/celebrate.test.tsx::Celebrate cap > holds to every cap it is given, and counts a burst against each)")).
- `Celebrate`'s confetti stays inside its own box instead of flying 80px past it over what is around it; give it room with layout classes (`h-24 w-full`) for a wider burst ([test](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/components/ouro/celebrate/celebrate.test.tsx "verify:testExists(registry/ouro/components/ouro/celebrate/celebrate.test.tsx::Celebrate > throws twelve pieces in every direction, at two distances, in the theme's tones, inside its own box and hidden from screen readers)")).
- New: `ouro-testing`: [`commands.compositedLayers()` lists the layers Chromium's compositor draws on their own and the element each draws, so a test proves that motion lets its layers go once it settles](https://github.com/ourostack/ouro-ui/blob/main/docs/guides/testing.md#counting-composited-layers "verify:fileLine(registry/ouro/lib/ouro/testing/commands.test.ts, /compositedLayers lists a layer for an element only while it has will-change: transform/)"); MessageList's tests now hold its scroll springs to it: no message keeps a layer, `will-change` or a transform once it rests.
- Fixed: ConversationList [renders only the rows the first view reaches on a short list's first commit, and the rest once it has painted, so the first mount costs what a screenful does](registry/ouro/components/ouro/conversation-list/conversation-list.windowing.test.tsx "verify:testExists(registry/ouro/components/ouro/conversation-list/conversation-list.windowing.test.tsx::ConversationList windowing with sections > renders a short list's first commit with only the rows the first view reaches and the rest after it paints)").
- Fixed: ConversationList [renders each row as a memoised component, so a selection change re-renders only the row that was open and the row that opens, and a windowed list's first commit mounts only the window](registry/ouro/components/ouro/conversation-list/conversation-list.windowing.test.tsx "verify:testExists(registry/ouro/components/ouro/conversation-list/conversation-list.windowing.test.tsx::ConversationList windowing with sections > mounts only the visible window of a windowed list's sections on the first commit, and re-renders only the two rows a selection switch touches)").
- Fixed: ConversationList [places its rows after a render only when its rows, window, heights or open row change, and learns of a row that changes size from a resize observer, so a render with the same rows costs the page no forced layout](registry/ouro/components/ouro/conversation-list/conversation-list.windowing.test.tsx "verify:testExists(registry/ouro/components/ouro/conversation-list/conversation-list.windowing.test.tsx::ConversationList windowing > lays nothing out when it renders again with the same rows, and measures a row that changes size once the page is laid out)").
- Changed: the Cookbook theme [carries Spoonjoy's photo-action colours and its own Ouro action, card and heading mappings, synced from spoonjoy-v2 493f42d7](site/src/themes/cookbook.css "verify:fileLine(site/src/themes/cookbook.css, /--sj-photo-action: #d6a46a;/)").
- Lightbox: thumbnails are fetched as they are drawn; the `loading="lazy"` on them is gone, so pictures below the fold, in the grid or in `layout="mosaic"`, are there when the reader scrolls to them. (A list that draws only what is near its view, such as a long MessageList, draws them, and so fetches them, as they come near.)
- Fixed: Menu: a menubar's open menu, and an open submenu, no longer leave two unnamed buttons in the menubar or menu in Safari and other WebKit on Apple platforms, where Base UI makes its focus guards buttons for VoiceOver; axe reported aria-required-children there (#663) ([test](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/components/ouro/menu/menu.test.tsx "verify:testExists(registry/ouro/components/ouro/menu/menu.test.tsx::MenuBar > holds only its menus while one is open, where WebKit on Apple platforms makes the focus guards beside it buttons)"))
- Fixed: MessageList [opens a conversation with its newest message in view in the first frame when its messages settle shorter in a later render of the same task, as long messages folding behind See more do, rather than a frame later](registry/ouro/components/ouro/message/message-list.test.tsx "verify:testExists(registry/ouro/components/ouro/message/message-list.test.tsx::MessageList switching conversations > opens a conversation with its newest message in view in the first frame when its long messages fold shorter in the same task, as behind See more)").
- `Moment` takes `kind="ask"`, for something the app or an agent working for the person asks them to look at, shown with `size="inline"` in a slot of its own such as a header strip, never over the content, and heard with `announce`; `dismissFor` ("hour", "day", "week", "month") makes a dismissal through `dismissKey` last that long, so an ask can come back later but not straight away ([test](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/components/ouro/moment/moment.test.tsx "verify:testExists(registry/ouro/components/ouro/moment/moment.test.tsx::Moment ask > docks in the slot it is given as one row, is heard when asked, and comes back after dismissFor)")).
- `Moment` takes `kind="first-run"`, and the root says `data-moment="first-run"`, so the kinds read empty, loading, error, first-run, success and ask; `kind="welcome"` still works as first-run's older name ([test](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/components/ouro/moment/moment.test.tsx "verify:testExists(registry/ouro/components/ouro/moment/moment.test.tsx::Moment > takes welcome as first-run's older name, and says first-run)")).
- Added: Navbar: `menu`, what its phone sheet holds in place of the links, such as a section's own pages under its name or a filter over a long list; choosing a link in it closes the sheet ([test](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/components/ouro/navbar/navbar.test.tsx "verify:testExists(registry/ouro/components/ouro/navbar/navbar.test.tsx::Navbar > shows the menu prop in the sheet in place of the links, and closes it when a link there is chosen)")).
- Fixed: Navbar: a link in the phone sheet opened in a new tab or window, with a modifier key held, leaves the sheet open ([test](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/components/ouro/navbar/navbar.test.tsx "verify:testExists(registry/ouro/components/ouro/navbar/navbar.test.tsx::Navbar > leaves the sheet open for a link opened elsewhere, with a modifier key held)")).
- Changed: Navbar: once the menu button shows, the phone sheet is built while the page is idle and kept, hidden, between opens, so a press only shows it, and the `menu` prop mounts ahead of that first press; it is built again once each close has finished, so each open starts with the state it first had ([test](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/components/ouro/navbar/navbar.test.tsx "verify:testExists(registry/ouro/components/ouro/navbar/navbar.test.tsx::Navbar > opens afresh after each close: the menu prop's state and the sheet's scroll as the first open had them)")). The hidden sheet holds what the open one does, its labels and its links' names among them: at phone width, once the page is idle, a test that finds something in the bar by its label or text alone (`getByLabelText("Menu")`, `getByText("Recipes")`) also finds its copy in the sheet, so find it by its role ([test](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/components/ouro/navbar/navbar.test.tsx "verify:testExists(registry/ouro/components/ouro/navbar/navbar.test.tsx::Navbar > builds the sheet while the page is idle once the menu button shows, and keeps it, hidden, between opens)")).
- Link-preview cards now print ui.ouroboros.bot, the site's new host, in their corner.
- New: `OuroProvider`'s `quiet`, for people who want less: `Moment` shows its words without art or a celebration, `Celebrate` its message without confetti, and `<html>` carries `data-ouro-quiet` so an app can hide its own decoration ([test](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/lib/ouro/ouro-provider.test.tsx "verify:testExists(registry/ouro/lib/ouro/ouro-provider.test.tsx::OuroProvider quiet > tells components the person asked for less, and marks the page while it is on)")).
- `Moment`'s `quiet` is words only: the compact row drops its 40px art (a loading spinner stays), and `MomentProvider` without `quiet` passes `OuroProvider`'s setting through ([test](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/components/ouro/moment/moment.test.tsx "verify:testExists(registry/ouro/components/ouro/moment/moment.test.tsx::Moment quiet > keeps its words and drops its art and celebration under OuroProvider's quiet, unless MomentProvider or the prop says otherwise)")).
- New: `portholeView` takes [an area's own `freshWithinMs`](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/lib/ouro/porthole-view.test.ts "verify:testExists(registry/ouro/lib/ouro/porthole-view.test.ts::portholeView > an area's own freshWithinMs > replaces the view's for that area alone, up to and including the window itself)"), so an area read on an interval stays fresh for its own window, with a `note` on how it is kept.
- Changed: Porthole's fresh headline reads ["Up to date" by default](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/lib/ouro/porthole-view.test.ts "verify:testExists(registry/ouro/lib/ouro/porthole-view.test.ts::portholeView > says Up to date while every area was verified within freshWithinMs)"), no longer "Updated just now", since an area's own `freshWithinMs` can be longer than a minute; pass `labels.fresh` to choose other words.
- AgentPresence, Chart, ConversationList, ImageCropper, NavigationRail, Slider, SyncStatus and TimeGrid [build their lookup maps, sets and merged labels once per change to their inputs, not on every render](https://github.com/ourostack/ouro-ui/blob/main/scripts/source-rules.test.mjs "verify:testExists(scripts/source-rules.test.mjs::no component, helper or kit file builds an index in render: each is memoised on its inputs or built at module scope)"): a scroll in a long ConversationList, a drag of a Slider or an arrow key in a TimeGrid no longer redoes that work. TimeGrid lays out its events once per change to the events, the days or their formats.
- Fixed: Sheet, Dialog: off iOS the backdrop reads no layout as it mounts, which laid out the whole page in the middle of the press that opened it ([test](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/components/ouro/sheet/sheet.test.tsx "verify:testExists(registry/ouro/components/ouro/sheet/sheet.test.tsx::Sheet iOS backdrop rule > reads no layout as the backdrop mounts, where the backdrop is fixed)")).
- Fixed: Sheet: Base UI's drawer variables are registered as the sheet's code loads, not as the first sheet opens, which restyled the whole page in the middle of that press ([test](https://github.com/ourostack/ouro-ui/blob/main/site/e2e/site-menu.spec.ts "verify:testExists(site/e2e/site-menu.spec.ts::on a phone the menu's first open registers no CSS property, on the home page or a docs page, so it restyles no more of the page than the sheet)")).
- Fixed: ScrollArea: keyboard focus on the area shows its scrollbar ([test](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/components/ouro/scroll-area/scroll-area.test.tsx "verify:testExists(registry/ouro/components/ouro/scroll-area/scroll-area.test.tsx::ScrollArea > is a keyboard-scrollable region named by label)")) through a rule on the scrollbar's sibling, the area's viewport, in place of a `:has()` rule on the area ([source](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/components/ouro/scroll-area/scroll-area.tsx "verify:fileLine(registry/ouro/components/ouro/scroll-area/scroll-area.tsx, /peer-focus-visible\/scroll-viewport:opacity-100/)")), which a change of focus anywhere on the page made the browser match again.
- Fixed: Sheet: opening a sheet restyles its content once, not once more for each of the variables Base UI sets as it opens: the keyboard's inset is 0px on the portal already, so Base UI's 0px on the viewport changes nothing, and the frontmost height is registered as not inherited ([test](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/components/ouro/sheet/sheet.test.tsx "verify:testExists(registry/ouro/components/ouro/sheet/sheet.test.tsx::feel > opens without restyling its content for Base UI's variables: the keyboard inset is already 0px above the viewport, and the frontmost height is not inherited)")).
- Fixed: Checklist, RouteProgress: their state rules select the row's cell and the bar's indicator as children (`[[data-starting-style]>&]:`, `[[data-open]>&]:`) in place of `group-data-*`, which Tailwind writes in a form Chrome cannot narrow, so while either was on the page every sheet, menu or popover that opened restyled all of its content again ([test](https://github.com/ourostack/ouro-ui/blob/main/site/e2e/site-menu.spec.ts "verify:testExists(site/e2e/site-menu.spec.ts::the site's CSS has no rule that makes an open restyle more than it changes)")).
- Fixed: ShowMore takes an optional `measureKey` (a message id), and a row that mounts again with the same key starts from its last measured fit, so it no longer mounts folded and unfolds, with its resize observer making no write when it agrees [show-more.tsx](registry/ouro/components/ouro/collapsible/show-more.tsx "verify:testExists(registry/ouro/components/ouro/collapsible/show-more.test.tsx::ShowMore as a row mounts again > starts a remounted row with its toggle already in the first commit)").
- Changed: the site, docs and `@ouro` namespace moved from https://ui.ouro.bot/ to https://ui.ouroboros.bot/, so the namespace is `"@ouro": "https://ui.ouroboros.bot/r/{name}.json"` and the docs links, the Inspector's included, name the new host ([source](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/components/ouro/inspector/inspector.tsx "verify:fileLine(registry/ouro/components/ouro/inspector/inspector.tsx, /https:\/\/ui\.ouroboros\.bot\/docs\//)")). The old host forwards to the same path on the new one, so an app's existing `components.json` keeps working until it switches.
- Fixed: Toaster [reads which edge it sits at once the page is laid out, not inside the commit that mounts it, so mounting it at launch costs the page no forced layout](registry/ouro/components/ouro/toast/toaster.test.tsx "verify:testExists(registry/ouro/components/ouro/toast/toaster.test.tsx::Toaster > lays nothing out when it mounts, and reads its edge once the page is laid out)").
- Fixed: Toolbar [measures its entries only when their labels, icons, order or the size change, so a render with the same items, or new handlers and pressed states, costs the page no forced layout](registry/ouro/components/ouro/toolbar/toolbar.test.tsx "verify:testExists(registry/ouro/components/ouro/toolbar/toolbar.test.tsx::Toolbar overflow > lays nothing out when it renders again with new items that look the same, and measures again when a label changes)").
- Fixed: Toolbar [measures its entries again when a font loads, in either direction, so the row never clips and More is never left empty or full by stale widths](registry/ouro/components/ouro/toolbar/toolbar.test.tsx "verify:testExists(registry/ouro/components/ouro/toolbar/toolbar.test.tsx::Toolbar overflow > measures its entries again when a font loads, so a face that widens the labels moves the controls that no longer fit into More)").
- Fixed: Toolbar [measures its entries again when their text grows without the row resizing, as with a larger root font size](registry/ouro/components/ouro/toolbar/toolbar.test.tsx "verify:testExists(registry/ouro/components/ouro/toolbar/toolbar.test.tsx::Toolbar overflow > measures its entries again when the text grows without the row resizing, as with a larger root font size)").
