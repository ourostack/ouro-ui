# Changes in this release

- New: A2UISurface's confirm sheet shows an id's name as the row, with the id [small beside it](registry/ouro/components/ouro/a2ui-surface/a2ui-surface.test.tsx "verify:testExists(registry/ouro/components/ouro/a2ui-surface/a2ui-surface.test.tsx::A2UISurface > shows a confirm row's name, with its id small beside it, and a row with no name shows its value alone)"), and takes a `label` resolver that [names ids from the app's own data](registry/ouro/components/ouro/a2ui-surface/a2ui-surface.test.tsx "verify:testExists(registry/ouro/components/ouro/a2ui-surface/a2ui-surface.test.tsx::A2UISurface > passes the app's resolver each confirm row's id, and shows the name it gives)"). It adopts core v0.9.0's [confirm-names case](test/fixtures/a2ui/core.json "verify:fileLine(test/fixtures/a2ui/core.json, /cases\/confirm-names\.json/)").
- New: Ouro AX's command [names its exit code](registry/ouro/ax/cli.test.mts "verify:testExists(registry/ouro/ax/cli.test.mts::a data result exits with the code its command names in the tool's table, and --json prints the data unchanged)"). A command that returns data takes `exit`, a name from the tool's exit table, so `--json` prints the data as before and the process exits with that code; a name the table does not have is refused.
- Ouro AX: `didYouMean` tries the nearest name first, then a unique prefix, so `--n` suggests `--in` rather than `--names`.
- New: Ouro AX's `defineCli` takes `command` for a tool with one thing to do, which [runs with no command word](registry/ouro/ax/command.test.mts "verify:testExists(registry/ouro/ax/command.test.mts::a tool with one command reads every token as the command's arguments and flags, with no command word)"): `ouro-images <folder>`. A tool with `commands` still refuses a word it doesn't know.
- New: Ouro check's gated `hero-dark-art` rule [finds a Hero with no night art](test/check-theme-in-page.test.ts "verify:testExists(test/check-theme-in-page.test.ts::findThemeIssues: hero-dark-art > finds a hero whose picture has no night art, in light mode too, named by its words)"), a picture in its frame with no dark twin, so an app that shows the day scene in dark mode fails the check until it passes `picture={{ light, dark }}`.
- Changed: `ouro-check` runs on [Ouro AX](registry/ouro/ax/command.test.mts "verify:testExists(registry/ouro/ax/command.test.mts::a tool with one command reads every token as the command's arguments and flags, with no command word)"), with `merge` beside it as a command word, so its `--help` and `--json` come from the kit. A refused option or target prints [one line that ends with the fix](scripts/check/check.test.mts "verify:testExists(scripts/check/check-command.test.mts::Ouro check's command > refuses a target that is no folder or URL in one line that names the fix, and a mistyped merge names merge)"), and [exits 2](scripts/check/check.test.mts "verify:testExists(scripts/check/check-command.test.mts::Ouro check's command > prints the kit's help for --help, and refuses an unknown flag in one line that names its fix, with exit 2)"). Gated findings still [exit 3](scripts/check/check.test.mts "verify:testExists(scripts/check/check-command.test.mts::Ouro check's command > exits 3 on gated findings, writes the step summary, and exits 0 when the config waives them)"). It now installs to [`@lib/ouro/check/`](scripts/registry.mts "verify:fileLine(scripts/registry.mts, /@lib\/ouro\/check\//)"), beside the kit it imports, where it was `~/lib/ouro/check/`.
- Fixed: Mounting a ToggleGroup skips Base UI composite's per-item style check, which forced a style recalculation.
- CI's design check now splits across more jobs, so a pull request waits less for its screen check.
- Pull request CI now ends by merging current main into the pull request and re-running the registry, docs, site build and CSS size checks, so pull requests that pass alone cannot break main together.
- New: Heading [tightens each size by the theme's `--ouro-heading-tracking`](registry/ouro/components/ouro/text/heading.test.tsx "verify:testExists(registry/ouro/components/ouro/text/heading.test.tsx::Heading tracking > scales the tightening by the theme's --ouro-heading-tracking, so a serif heading font can keep its own spacing)"), a share that defaults to `1`, so a theme with a serif `--font-heading` sets it to `0.5`, or `0` for the font's own spacing, and Hero's headline is no longer crushed.
- Hero: the actions [sit right under the lede, on its edge](registry/ouro/components/ouro/hero/hero.test.tsx "verify:testExists(registry/ouro/components/ouro/hero/hero.test.tsx::Hero > sets the actions right under the lede, a step further from it than the lines of text, on the lede's edge)"), now a step further from it than the lines of text are from each other, so the page's main button belongs in `actions` rather than inside `description`.
- Hero: with `priority` on both twins, [only the twin shown at first paint loads, eagerly, from server HTML](registry/ouro/components/ouro/hero/hero.test.tsx "verify:testExists(registry/ouro/components/ouro/hero/hero.test.tsx::Hero > loads the twin shown at first paint eagerly from server HTML, and leaves the hidden one lazy)"), through a small inline script after the twins, so a dark page no longer waits on lazy night art or downloads the hidden day art; with `priority` on one twin, [that twin loads from the HTML and the other stays lazy](registry/ouro/components/ouro/hero/hero.test.tsx "verify:testExists(registry/ouro/components/ouro/hero/hero.test.tsx::Hero > keeps a lone priority twin eager in the HTML and the other lazy, at high fetch priority)"), dark as well as light. `HeroPicture`'s docs show the preload for the shown art.
- Hero: [each `source` takes its own `width` and `height`](registry/ouro/components/ouro/hero/hero.test.tsx "verify:testExists(registry/ouro/components/ouro/hero/hero.test.tsx::Hero > gives each source its own width and height, so a source of another shape holds its box before it loads)"), so a phone crop of another shape holds its box before it loads.
- The theming guide shows how a site that marks dark mode with `data-theme` and the system setting redefines Tailwind's `dark` variant, which [Hero's night art follows](registry/ouro/components/ouro/hero/hero.tsx "verify:fileLine(registry/ouro/components/ouro/hero/hero.tsx, /dark: \"hidden dark:block\"/)").
- Hero: `picture` takes `{ light, dark }`, the same scene by day and at night, and [shows the one that matches the page's dark mode](registry/ouro/components/ouro/hero/hero.test.tsx "verify:testExists(registry/ouro/components/ouro/hero/hero.test.tsx::Hero > shows the dark picture only while the page is in dark mode)"), the `.dark` class a stored theme toggle sets, in CSS, so there is no flash on load. Unless it has `priority`, the night art [loads lazily](registry/ouro/components/ouro/hero/hero.test.tsx "verify:testExists(registry/ouro/components/ouro/hero/hero.test.tsx::Hero > keeps a lone priority twin eager in the HTML and the other lazy, at high fetch priority)"), so a page in light mode doesn't download it. Both are required: a hero has night art, and a hero missing it [says so in development](registry/ouro/components/ouro/hero/hero.test.tsx "verify:testExists(registry/ouro/components/ouro/hero/hero.test.tsx::Hero > says so when the night art is missing, and shows the day art in both modes)").
- Hero: [the lede's first block has no top margin and its last no bottom margin](registry/ouro/components/ouro/hero/hero.test.tsx "verify:testExists(registry/ouro/components/ouro/hero/hero.test.tsx::Hero > clears the outer margins of the lede's first and last blocks, and keeps the space between them)"), so a paragraph in `description` needs no `m-0`, and a margin class of the app's own on it still wins.
- New: once the picture shown has loaded, Hero's media frame [carries `data-loaded`](registry/ouro/components/ouro/hero/hero.test.tsx "verify:testExists(registry/ouro/components/ouro/hero/hero.test.tsx::Hero > marks the frame data-loaded once the picture shown has loaded, from server HTML with no hydration)"), set from the server's HTML by a small inline script and by Hero itself [after hydration](registry/ouro/components/ouro/hero/hero.test.tsx "verify:testExists(registry/ouro/components/ouro/hero/hero.test.tsx::Hero > marks a picture that loaded before hydration once it hydrates, where the page's scripts did not run)") or [a client render](registry/ouro/components/ouro/hero/hero.test.tsx "verify:testExists(registry/ouro/components/ouro/hero/hero.test.tsx::Hero > marks the frame data-loaded on the client too, once the picture shown has loaded)"), so a site or a test can wait on `[data-slot="media"][data-loaded]`. The hidden twin's load doesn't count.
- Hero: the dark picture [takes the light one's `focus` unless it has its own](registry/ouro/components/ouro/hero/hero.test.tsx "verify:testExists(registry/ouro/components/ouro/hero/hero.test.tsx::Hero > gives the dark picture the light one's focus unless it has its own)"), as it already took its `alt`, so a focal point set on the day art holds at night. In the split layout the picture [keeps its own ratio](registry/ouro/components/ouro/hero/hero.test.tsx "verify:testExists(registry/ouro/components/ouro/hero/hero.test.tsx::Hero > shows the whole picture in the split layout, so a wide crop never cuts its subject in the narrower column)") rather than the stage's wide `crop`, so the narrower column shows the whole scene.
- New: a Hero picture's `placeholder` [paints a colour in its box while the image loads](registry/ouro/components/ouro/hero/hero.test.tsx "verify:testExists(registry/ouro/components/ouro/hero/hero.test.tsx::Hero > paints each picture's placeholder behind it while it loads, and the day's never at night)") in place of an empty hole. It fills the box its `width` and `height` already reserve, so nothing moves. The dark picture takes its own, not the light one's. Take the colour from your image pipeline, such as the `dominant` colour of `sharp(file).stats()`.
- Hero: the picture's frame [has 24px squircle corners](registry/ouro/components/ouro/hero/hero.test.tsx "verify:testExists(registry/ouro/components/ouro/hero/hero.test.tsx::Hero > frames the picture with 24px squircle corners)"), Ouro's corner shape, in place of 4px round ones.
- Changed: `ouro-images` runs on [Ouro AX](registry/ouro/ax/command.test.mts "verify:testExists(registry/ouro/ax/command.test.mts::a tool with one command reads every token as the command's arguments and flags, with no command word)"), so its `--help` and `--json` come from the kit. A refused option prints one line that ends with the fix to run and [exits 2](scripts/images/images.test.mts "verify:testExists(scripts/images/images.test.mts::Ouro images' command > refuses what it cannot run with one line that names the fix, and exits 2)"). It now installs to [`@lib/ouro/images/`](scripts/registry.mts "verify:fileLine(scripts/registry.mts, /@lib\/ouro\/images\//)"), beside the kit it imports, where it was `~/lib/ouro/images/`, so an app whose `lib` alias sits under `src/` finds it there.
- NavigationRail mounted with overflowing items now settles its fit in a single measure, so the first frame costs less.
- The install prepare cache keys on the install scripts only, so a pull request that changes other scripts restores the prepared app.
- Resizable keeps one context value while its panels, labels, sizes and options stay the same, so re-rendering the group leaves memoized content inside it alone.
- New: a dispatch-only workflow measures the squircle polyfill in real Safari on a hosted macOS runner, idle work and typing latency with it off and on.
- Scheduled install also installs with the unpinned shadcn CLI from main.
- Skeleton's shipped end-to-end spec judges shimmer={false} in WebKit alone, fails when a skeleton animates with shimmer={false}, and compares its dropped frames with a permutation test instead of a fixed margin.
- Source rules: the corner, switch and hero messages name the squircle corner shape, the Quiet glass tokens and the light and dark hero picture.
- Changed: `OuroProvider` stops registering the `hyperellipse` squircle polyfill, which slowed typing and scrolling where `corner-shape` is not native and added a runtime dependency; those engines show round corners unless an app installs `lib-squircle-polyfill` and calls `registerSquirclePolyfill()` once.
- Changed: standard rounded corners become squircles (`--ouro-corner-shape`, native `corner-shape`; the `hyperellipse` polyfill is opt-in), radii grow by half again, and avatar circles become squircles; switches, radios, slider thumbs and presence dots stay round.
- Fixed: the Tabs indicator skips measuring the tab list when its parent re-renders and nothing moved.
- Fixed: `vague-failure-copy` no longer reads text that is not copy: the first argument of [`includes`, `startsWith`, `endsWith`, `has` and `test`](scripts/kits/source-rules.test.mjs "verify:testExists(scripts/kits/source-rules.test.mjs::vague-failure-copy > skips the first argument of a membership test: includes, startsWith, endsWith, has and test)"), a [`Set` only used for membership](scripts/kits/source-rules.test.mjs "verify:testExists(scripts/kits/source-rules.test.mjs::vague-failure-copy > skips a string in a Set that is only used for membership: inline, or a const Set used for nothing but .has)"), a [class name in `error.name || "Error"`](scripts/kits/source-rules.test.mjs "verify:testExists(scripts/kits/source-rules.test.mjs::vague-failure-copy > skips the class name in a name fallback, and nothing else after error.name)"), and a [heading that names the topic](scripts/kits/source-rules.test.mjs "verify:testExists(scripts/kits/source-rules.test.mjs::vague-failure-copy > skips a heading or label that only names the topic: a plural errors or failures, no action before it)") such as "Machine errors". A protocol's own wording, such as JSON-RPC's "Parse error", is still flagged, so it goes in `failureCopyAllow` with its reason.
- Changed: the squircle polyfill (`lib-squircle-polyfill`) ships its engine as source in `lib/ouro/squircle/` and does not depend on the `hyperellipse` package; its tests also run in Firefox and in WebKit and Chromium with native corner-shape hidden.
