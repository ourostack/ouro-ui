# Changes in this release

- New: an Autocomplete trigger with `catalogue` takes `skinTone`, so a `:` suggestion shows and inserts an emoji in the skin tone the person chose in EmojiPicker, given the same `skinTone`, instead of the default tone.
- Fixed: Autocomplete keeps the list closed over the text a pick inserted until the person edits it, so the next Enter in a `Composer` sends; before, a selection change that left the picked name and came back (as an app's update of the text can make) reopened the list for a name its trigger still matched, such as with `allowSpaces`, and that Enter picked the same name again ([test](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/components/ouro/autocomplete/autocomplete.test.tsx "verify:testExists(registry/ouro/components/ouro/autocomplete/autocomplete.test.tsx::Autocomplete > keeps a picked name closed when a selection change leaves it and comes back, as an app's update of the text can make, so the next Enter sends)")).
- Fixed: Autocomplete scrolls only its own list to the active suggestion; it used `scrollIntoView`, which could also scroll a box around the list, such as an app's frame with `overflow: hidden`, and the page ([test](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/components/ouro/autocomplete/autocomplete.test.tsx "verify:testExists(registry/ouro/components/ouro/autocomplete/autocomplete.test.tsx::Autocomplete > scrolls only its own list to the active suggestion, never a box around it)")).
- New: `Avatar` takes `shape="hexagon"`, a rounded hexagon for an AI agent, as Teams draws agents, with initials, an icon or a picture inside it and no presence dot ([docs](https://github.com/ourostack/ouro-ui/blob/main/docs/Avatar.md), [test](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/components/ouro/avatar/avatar.test.tsx "verify:testExists(registry/ouro/components/ouro/avatar/avatar.test.tsx::Avatar shapes and icons > draws an agent as a rounded hexagon at every size, its initials and picture inside it)")).
- Fixed: Ouro AX: a number flag given more than its maximum gets the maximum as its fix, as `--limit 2000` gets `--limit 1000` on a flag that allows up to `1000`, instead of the smallest allowed number; a value too small or not a number still gets the smallest ([test](https://github.com/ourostack/ouro-ui/blob/main/registry/ouro/ax/command.test.mts "verify:testExists(registry/ouro/ax/command.test.mts::a number out of range gets the nearest allowed number as its fix: the most when too big, else the least)")).
