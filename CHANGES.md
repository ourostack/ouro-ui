# Changes in this release

- Component roots no longer set `m-0`, so a parent's `space-y-4` keeps its gap around a Field, TextField, TextArea, Select, Checkbox, Switch, Button and every other component; roots with a browser margin (Text, Heading, Fieldset, Chart, DescriptionList, and Stack or Row as a list) clear it with `[@layer_ouro-reset]:m-0`, which any margin utility beats. If you relied on a root's `m-0` to cancel a margin your own CSS sets on `button`, `p` or `div`, add `className="m-0"` there.
- Field: the required marker is drawn with CSS on a new element around the label (`[data-ouro-label]`, or `[data-ouro-legend]` on a group) and is no longer a `<span data-ouro-required>*</span>` inside it, so the label's text and the control's accessible name are the label alone and `getByLabelText("Email")` and Playwright's `getByLabel("Email", { exact: true })` find a required field. `FieldLabel`'s `className` now goes on that outer element, a group's label `id` is on the inner `<span>`, and `[data-ouro-required]` is now an attribute of the outer element; update selectors and tests that read the old span or expected "Email*".
- TextField and DatePicker: the clear, show-password and choose-date buttons are named by visually hidden text instead of `aria-label`, so Playwright's `getByLabel("Password")` and `getByLabel("Date")` match the field alone. `getByRole("button", { name: "Show password" })` still works; replace `button[aria-label="…"]` selectors with `[data-ouro-show-password]`, `[data-ouro-clear]` or `[data-ouro-choose-date]`.
- TextField and TextArea: new `variant="plain"` (no border, background or padding, for a field inside a frame your app draws) and `size="lg"` (20px text; TextField is 56px tall, 48px on desktop); the defaults `"outline"` and `"md"` look as before. `size` replaces the input's own numeric `size` attribute on TextField; set a width with `className`.
- TextField: `type="datetime-local"`, `"file"`, `"month"` and `"week"` now warn with the component to use (DatePicker, FileField), as `"number"` does with NumberField, and the docs page lists what is not a TextField.
- Every form control and `Form errors`: an error message can be a React node as well as text (`error={<>Already imported. <Link href="/recipes/soup">Open it</Link></>}`), still announced and linked with `aria-describedby`; the types are `ErrorMessage` and `ErrorMessages` from `lib/ouro/use-field`.
- Form: bind the accepted answer inside its one `errors` prop with `formErrors(answer, messages)` from `@/lib/ouro/form-answer`, replacing the unreleased `result` prop. A genuine new answer restores cleared messages and focuses/replaces its alert once, even for an equal refusal; stable answers render the latest uncleared projection while preserving their clear mask through pending/prevented submits, omitted keys and temporarily absent answers. Cached/reused or primitive answers need `{ key: acceptedAnswerKey }`, advanced only on actual acceptance, not submit start. The constructor never retains or serializes unselected answer payloads; JSON/spread/cloning loses private identity, so reconstruct beside Form with the accepted local source or a safely transported acceptance key. Flat records remain content-only and cannot identify equal new answers. A key may hold `undefined`, `null`, `""` or `[]`; `FormErrors` is now `Record<string, ErrorMessages | null | undefined>`, so code that reads `errors.email` as `string | string[]` needs a check for the wider type.
- Form: the message at the top of the form is in the page only while there is a message, and each answer adds a new `role="alert"` element with its text, so screen readers announce it and `getByRole("alert")` finds nothing on a form without one. Field errors are not alerts: assert them with `toHaveAccessibleDescription` or `getByText`. Tests that expected an empty `[data-ouro="form-message"]` element need updating.
- Form: the development warning for an `errors` key no field is named now lists the key, the form's field names and the exact `errors={{ … }}` to pass, and says nothing about a key with no message.
- Form and Field docs now state the order of checks (the browser's, then `onSubmit`, then the server), that a page loading with errors moves no focus, and how to put helper text after the control (`<FieldDescription>` after `<FieldControl>` inside a `Field`).
- An `aria-required`, `aria-busy`, `aria-disabled` or `aria-describedby` you pass to FieldControl (and so TextField, TextArea, NativeSelect), Button, Message or Chart now reaches the element instead of being overwritten by the component's own value.
- TextArea: `autoGrow` no longer reports "ResizeObserver loop completed with undelivered notifications" on the window when its width changes; it refits in the next frame.
- Sheet: the viewport is `overflow-clip`, so focusing or scrolling a control into view while a sheet is closing or dragged can no longer scroll the sheet off its edge.
- Test kit: `commands.emulateMedia` accepts `forcedColors: "active" | "none"`.
- Link: on a coarse pointer a link that stands alone ("Forgot password?", a link in a list item or table cell) is an `inline-flex` box at least 44px tall and wide with its text centred, which takes its room in the layout, so a list of links is taller on a phone and short links also reserve their horizontal tap area. A link in running text (a `<p>`, `<label>`, `<dt>`, `<dd>`, `Text`, or a field's description or error, a Form's message, an Alert's text, an Item's description) stays as tall as its line; the new `inline` prop says the same anywhere else, and `inline={false}` gives a link that is alone in its `Text` the box. With a mouse nothing changes.
- Field: the required marker's alternative text is empty (`content: "*" / ""`), so screen readers in reading mode no longer say "star", and it fades when the field is disabled, including a group's legend and a Select's label.
- Checkbox and Switch: the label is padded to its line height, so a tap between two lines of a wrapped label toggles the control.
- FileField, Combobox and NumberField: a file's remove button, the clear and chip remove buttons, and the steppers are named by visually hidden text instead of `aria-label`, so a loose `getByLabel` for the field finds the field alone. `getByRole("button", { name: "Remove photo.jpg" })` still works; replace `button[aria-label="…"]` selectors with `[data-ouro-file-remove]`, `[data-ouro-combobox-clear]`, `[data-ouro-combobox-chip-remove]`, `[data-ouro-increment]` or `[data-ouro-decrement]`. A remove button's hidden text holds the file or item name, so a loose `getByText("pasta.png")` also matches it; pass `{ exact: true }`. ColorField's swatch is a color input, which only label text can name, so it keeps its `aria-label`; its docs say how to find the field.
- Install: no component brings `ouro-base` any more, so add it once per app (`npx shadcn@latest add ourostack/ouro-ui/ouro-base#<tag>`); after that, adding or updating a component leaves your stylesheet byte for byte as it was.
- Install: a component brings only the helpers it imports, one item per file in `lib/ouro` (`lib-cn`, `lib-use-field`, …; `OuroProvider` comes with every component that renders links and with `tooltip`; any other app adds `lib-ouro-provider` by name), and a `-tests` item brings the tests of everything its component installs. CI verifies 100% line and branch coverage of the installed runtime files for button, dialog, sheet, the forms set and their union; other items receive their full test dependency closure but are not measured individually.
- Install: test tools (Vitest, Playwright, Storybook) are listed without a version, so an add never changes the versions you pinned; each `-tests` item names the minimum in `meta.requires` (Vitest 4.1.11, Playwright 1.58.1, Storybook 10.2.10), and the Testing guide lists them.
- Theme: `ouro-base` now defines `--input` and `--radius` with their Tailwind mappings where your theme has none, so a field has its 1px border and rounded corners in an app without the Ouro theme or a shadcn preset.
- Testing: every installed Playwright spec imports `test` and `expect` from `e2e/ouro-fixtures.ts`, a file you own (create it once; `ouro-tests` prints it), so your own fixtures apply to Ouro's specs and an update never rewrites the import.
- Testing: `ouroTestProjects` takes `page: { width, height }` for the browser page size, which Vitest 4 needs because it has no per-project viewport option.
- Testing: `pressTab()` in `lib/ouro/testing/tab.ts` moves focus as Tab does in every browser; Ouro's tests use it, so they pass in WebKit on a Mac whatever the system's "Tab reaches buttons" setting is.
- Testing: the setup file now fails a test for any console output, including `console.log`, `console.info` and `console.debug`, in every project that uses it; mock the method when a message is expected.
- Renamed `lib/ouro/use-dev-warnings.ts` to `use-dev-messages.ts` so the file name does not trip a "no warnings" source rule; the hook is still `useDevWarnings`. After updating, delete the old file.
- Select: the "is disabled and read-only on request" test no longer logs Base UI's "changing the default value" message, and a new test shows that `multiple` posts one form entry per chosen value (`formData.getAll`).
- Docs: new Installing, Testing and Forms guides and an OuroProvider page with complete React Router and Next.js adapters; `radio`, the menu parts and every other exported item now have a page, and CI checks that every link in the README, the docs and the install messages opens a page, letter case included.
- Docs: Link says it is for text links and names what to use for a card, a row or the links between pages; Alert says it is for a message that belongs to no field and no form; Select documents `multiple` posting and that tests need real pointer events.
- Docs: `"use client";` at the top of each component is kept in an app with `"rsc": false`; the Installing guide explains why and how to silence the bundler's notice.
- Releases: after publishing the tag, the release run verifies the prepare PR merged and CI passed on main's new tip before dispatching Pages, then checks that the published `llms.txt` and README name that tag. Failed, missing or undispatched main CI blocks Pages; the release itself remains published.
- Upgrading: releases before this one installed every `lib/ouro` helper with any component, and an update deletes nothing. Follow step 5's read-only reference audit across the whole app before deleting a verified-unused historical helper and its own tests; unresolved references require keeping the file, not excluding it from coverage.
- In development, the first Ouro UI component to mount checks once per page that `ouro-base` is in the app's CSS and, if `--ouro-layer` is unset, logs the command that adds it; production builds contain no check.
- Install commands through the `@ouro` namespace now add `@ouro/ouro-base` first.
- New: `AuthLayout`, the sign-in page: a `Card` in the middle of the screen with `brand`, the `title` as the page's `<h1>`, `description`, the form, and a `footer` line under the card. `as="div"` is for a page that already has a `<main>`.
- New: `Breadcrumb`, the trail to the current page from `items` of `{ label, href, icon }`, the last one marked `aria-current="page"`. A trail longer than `maxItems` (default 4) keeps its first and last steps and puts the middle in a `Menu`, a bottom sheet below 640px, named by `moreLabel`.
- Carousel advances from the slide that just settled when Next or Previous is pressed before React updates the rendered index, without wrapping unless `loop` is enabled.
- New: Command, a command palette in a Dialog (a full-height sheet below 640px) with search, groups, shortcuts and an empty state; `useCommandShortcut("mod+k")` in lib/ouro opens it from anywhere on the page.
- Command: server-side search with `onQueryChange(query, { signal })`, whose signal aborts when a newer query replaces it, and `loading` with `loadingLabel` (default "Searching…"), announced once per opening; the empty state waits for loading to finish.
- Command: `onQueryChange` also runs with the current search text whenever the palette opens or swaps between dialog and sheet, so a reopened palette never shows the last search's results; `aria-keyshortcuts` uses ARIA key names (`ArrowUp`, `Escape`, `Enter`); `useCommandShortcut("?")` fires on Shift+/.
- Sidebar, Navbar and NavigationMenu mark the current page with a bar at the logical start edge, matching Menu in left-to-right and right-to-left layouts. Hover, open-panel and press highlights remain transient. Existing `currentPath`, `current` and `aria-current="page"` behavior is unchanged.
- Current panel labels gain emphasis without bolding their descriptions. All four components keep the mark visible in forced-colors palettes; `ouro-testing` accepts `emulateMedia({ forcedColors: "active" })` for these checks. Component-local opt-in tests cover the marks, so installed tests verify the same convention.
- lib/ouro gains `current-path.ts`: `currentHref(hrefs, currentPath)` picks the navigation link for the current page, which `Navbar`, `Sidebar` and `NavigationMenu` use for `currentPath`.
- A Dialog whose `trigger` comes from a Server Component no longer fails `next build` with "Element type is invalid" when React hands the trigger over as a lazy wrapper.
- `MenuItem` takes `current`, which marks a link item as the page being shown (`aria-current="page"`, a medium-weight label with a bar at the start edge, so it never looks like the highlighted row). `Sidebar` uses it for the nested links a collapsed rail opens in a menu.
- New: Menu, one API for a dropdown (`trigger`, a bottom sheet below 640px), a context menu (`contextTrigger`, right-click or long-press) and a `MenuBar`, with `items` data or `MenuItem`, `MenuCheckboxItem`, `MenuRadioGroup`, `MenuSub`, `MenuGroup` and `MenuSeparator` children; items take `shortcut`, `tone="destructive"` and `href`.
- Menu: the phone sheet ends with a Close item (`closeLabel`, default "Close") for screen-reader and switch users, and a submenu in the sheet no longer opens on hover.
- Changed: control motion and feel. Hover styles on Tabs, SegmentedControl, Accordion, Collapsible, Button, Badge, Toggle, Link, FileField, Checkbox, RadioGroup, NumberField, Calendar and the Message list and attachments apply only to a fine pointer that can hover (`pointer-fine:hover:`), so a tap on a phone leaves no hover state behind; Link, the FileField drop zone, the NumberField steppers and the ColorField swatch now respond the moment the pointer goes down, and the ScrollArea thumb darkens while dragged; Tabs and SegmentedControl no longer animate when an arrow key moves the selection, and their indicator and thumb slide on `translate` only (Tabs' indicator is now a 1px line scaled to the tab, with square ends, so it resizes smoothly too) in 200ms instead of a 750ms spring; the Switch thumb stretches by scaling and slides in 160ms, the Checkbox tick fades and grows in from 95% instead of drawing along its path, and the RadioGroup dot grows in from 95% instead of from nothing, in 150ms; the Slider thumb grows in 160ms; Progress fills by sliding a full-width bar (its indicator is now always full width, so an app that read the indicator's width should read its position, or the value); Chart marks draw in full at once instead of animating for up to 1.5s, and the `data-ouro-chart-animating` attribute is gone; Heading tracks tighter as text grows (none at 16px, -0.025em at 30px) instead of one fixed `tracking-tight`; the soft Button, soft Badge and pressed Toggle get a visible border under `prefers-contrast: more`; enter and exit fades on Accordion, Collapsible, Field messages, Button, Avatar, ShowMore, ScrollArea and Tabs panels use the `--ouro-ease-out` curve, and border and tint changes use `ease`.
- Added: the `ouro-testing` command `emulateMedia` takes `contrast: "more" | "no-preference"`, to test `prefers-contrast: more` styles.
- Dialog: opens in 300ms and closes in 200ms on the ease-out token (it was a 750ms spring with an `ease-in` exit); it stays centred, and its close button now scales and tints the moment it is pressed, with its hover gated to mice.
- Select, NativeSelect and Combobox: hover styles apply only with a mouse or trackpad, and the Select trigger (under a finger; a mouse opens the list at once), Select items, Combobox items, Combobox phone trigger and Combobox chip remove buttons show a pressed state at once; the Select list opens in 200ms and closes in 150ms, and its phone sheet now slides up on the drawer curve (it used to appear without sliding).
- Menu, MenuBar and Command items show a pressed state at once; on a desktop, a Command palette opens and closes without animating (the phone sheet still slides).
- New: `Navbar`, the bar across the top of an app, with `brand`, `items` and `actions`. The link for `currentPath` (your router's pathname), or the longest link above it, gets `aria-current="page"`. An item with `links` is a group: a `NavigationMenu` panel in the bar and a labelled group in the sheet. Below 640px, and whenever the links do not fit the bar, they collapse behind a menu button into a `Sheet` from the side; `menuLabel` and `closeLabel` name its controls. The menu opens once JavaScript has loaded.
- New: `NavigationMenu`, on Base UI's Navigation Menu: a row of `items` that are links or buttons opening a panel: `links` with descriptions in one or two `columns`, and any `content` beside them, such as a featured card. Panels open on hover or click, close on Escape and when a link is chosen, and the link for `currentPath` gets `aria-current="page"`.
- New: `Pagination`, with Previous, page numbers with gaps and Next, and the current page marked `aria-current="page"`. With `href` (a string with `{page}`, which a Server Component can pass, or a function) every page is a plain link that works with no JavaScript; with `onPageChange` the pages are buttons. Below 640px the numbers give way to "Page 3 of 12". Without `pageCount`, for a list with no count of its rows, it shows Previous and Next only, and `hasNextPage` enables Next. Every label is a prop: `label`, `previousLabel`, `nextLabel`, `pageLabel`, `summaryLabel`.
- New: `Reorderable`, a list from `items` (`{ id, label, content }`) that the user puts in order with each row's drag handle, a 44px target on a touch screen. Dragging is never the only way: a tap or click on a handle, Enter, or a screen reader's activation opens a `Menu` with Move up, Move down, Move to top and Move to bottom, with the ones that cannot apply disabled; and from the keyboard Space picks a row up, the arrow keys move it, Space drops it and Escape puts it back. A handle is a menu button and never also a toggle: a picked-up row is announced, and its handle's description says it is held (`heldLabel`). Each move is announced with the row's position ("Sear the ribs moved. Position 3 of 7."), and every spoken string and menu item is a prop with an English default (`handleLabel`, `instructionsLabel`, `heldLabel`, `pickedUpLabel`, `movedLabel`, `droppedLabel`, `canceledLabel`, `moveUpLabel`, `moveDownLabel`, `moveToTopLabel`, `moveToBottomLabel`, `closeLabel`). Holding a dragged row near the top or bottom edge scrolls the list or the page at the same speed on any screen, a touch that starts outside a handle scrolls as usual, and `onReorder(ids, { id, from, to })` reports each drop and each menu move once. A dragged row follows the pointer from where it took hold, resists past either end of the list, and drops in the gap the other rows have made for it on screen, however fast it is let go; it springs into that place with the speed it had, and a press stops it on the way so it can be picked up again. With reduced motion the rows are in place at once.
- A `ResizableHandle` follows the pointer that took it: a second finger on the handle no longer makes the panel jump.
- A touch that moves along a `ResizableHandle` scrolls the page: the handle sets `touch-action: pan-y` between side-by-side panels and `pan-x` between stacked panels, where it set `none`. When the browser takes a touch for a scroll, the panels go back to the sizes they had and `onLayout` is not called.
- A `ResizableHandle` shows its hover color only for a mouse (`pointer-fine:hover:`).
- A tap made right after a fast touch drag of a `ResizableHandle` now gets its click: the handle takes the drag's touch moves, so the browser starts no fling for the tap to stop.
- A `ResizableHandle` that loses the pointer with no release (it was hidden or disabled mid-drag) ends the drag and puts the panels back; before, the handle stopped answering the pointer.
- A Select whose `SelectItem` children come from a Server Component shows the chosen item's label in its trigger when React hands an item over as a lazy wrapper.
- A Sheet caught while it is still moving back to rest, or to a snap point, stays under the finger and follows from there. Before, it jumped to its rest position the moment it was touched, so a tap made right after a flick could land beside the button it aimed at.
- A Sheet's release and entry now take `--ouro-duration-sheet` (500ms) on `--ouro-ease-drawer`, with no bounce, and its backdrop fades over the same time and curve; both used the 750ms theme spring. A flick's release is still shortened by its speed.
- The variables a Sheet drag rewrites every frame (`--ouro-sheet-x`, `--ouro-sheet-y`, `--ouro-sheet-transform` and the new `--ouro-sheet-grab`) are registered as not inherited, so the sheet's content is not restyled on each frame of a drag. CSS inside a sheet that read them from the popup by inheritance now gets their initial value.
- A bottom Sheet with `snapPoints` keeps its bottom padding fixed while it is dragged; the padding changes when the sheet lands on another snap point. Before, it changed on every frame of the drag, which laid the sheet's content out again each time.
- ShowMore keeps each row's own key, and tells an appended page from a replaced list, when its `items` come from a Server Component and React hands them over as lazy wrappers.
- New: `Sidebar`, a column of links in `sections` with `header` and `footer`, the current page marked `aria-current="page"` from `currentPath`. An item can have a `badge` ("Inbox 12"), be a button (`onClick` without `href`), or nest one level of items under a disclosure button (`items`), which starts open when it holds the current page. From 640px up it collapses to a rail of icons with its own button (`collapsed`, `defaultCollapsed`, `onCollapsedChange`, `collapseLabel`; `collapsible={false}` removes it), and a `Tooltip` names each icon, where an item with nested links opens them in a `Menu` beside it; below 640px it is a menu button that opens the links as a `Sheet` drawer once JavaScript has loaded.
- New: `SidebarLayout` and `StackedLayout`, the shells of an app with a `Sidebar` or a `Navbar`. Each renders the page's `<main>`, starts with a "Skip to content" link (`skipLabel`) and keeps its navigation in view while the page scrolls; `bleed` removes the padding around the page, and `as="div"` is for a layout inside a page that already has a `<main>`. `SidebarLayout` shows a top bar with the sidebar's menu button and its `header` on a phone; `StackedLayout` centers the page in a column and keeps `footer` at the bottom.
- New: `lib/ouro/spring` and `lib/ouro/use-drag`, the gesture helpers behind `SwipeActions` and `Reorderable`, with no animation library. `spring({ from, to, velocity, element, onUpdate })` runs a spring on animation frames from an element's live position with its release velocity (px/ms), critically damped unless `damping: 0.8` is passed after a flick, and returns `stop()`, which says what is on screen, `retarget(to)` and `running`; with reduced motion it jumps to the target. The `element` carries `data-ouro-settling` while the spring runs, so styles can follow it and tests can wait for it to clear. `project`, `nearest` and `rubberband` are the math for snap points and for resistance past an end. `useDrag({ axis, onPress, onPressEnd, onStart, onMove, onEnd })` returns pointer handlers and a `ref` for a one-axis drag: it waits 10px before choosing the axis, leaves the other axis to the page's scroll, captures the pointer only once the drag has begun, ignores a second finger, and reports movement from the grab point with a velocity measured up to the release and whether that was a flick. `onPress` is where to stop a running spring, so it holds still under the finger, and `onPressEnd` where to start it again when the press was only a tap. Once a drag has begun the hook takes its touch moves (`preventDefault`, through the `ref`), because Chromium otherwise starts a fling when a fast drag ends, although nothing scrolls, and the first tap in the half second after gets no click.
- EditSheet restores cleared field errors and replaces its alert for every accepted save refusal, including equal messages and reused results. Pending work and results from a closed or unmounted opening do not mark a new edit.
- DatePicker restores its uncontrolled default and ISO submission value on native form reset, preserves controlled ownership and prevented resets, and keeps invalid defaults invalid. Its hidden readonly ISO backing control has native defaults independent of the displayed draft.
- Combobox keeps uncontrolled custom values and clears across responsive popup/sheet changes. Native reset restores its custom default without taking ownership from a controlled caller.
- Fixed: lifting the finger from the long press that opened SwipeActions' menu is no longer a tap. Chromium could send one, which closed the menu when the finger stayed down more than half a second after the menu opened.
- Fixed: SwipeActions' phone tests batch slow swipes into one command and keep the long-press clock still while a spring-catching finger starts moving, so command round trips do not turn the catch into a long press.
- New: `SwipeActions`, a list row (wrap an `Item`) whose `leading` and `trailing` actions a horizontal swipe reveals, with touch or pen. The row follows the finger from where it took hold, resists a pull toward a side with no actions, and springs to rest from where it is let go; a quick flick opens or closes it however short, and a press stops it on the way so a new swipe can catch it. The first action of a side is its primary one, and a swipe past 60% of the row runs it on release, so pair a destructive one with a toast Undo; a flick alone never runs an action. The swipe is never the only way: a long press on the row with a finger or a pen opens every action as a `Menu` there (text selection and the iOS callout are off while a finger is down; a mouse's right-click keeps the browser's own menu, with "Open in new tab" for a row that is a link), and the row's actions button, named with `label` (`actionsLabel`, default "Actions for {label}"), opens the same menu: it shows with a mouse and is kept for the keyboard and screen readers on a touch screen. A vertical swipe on a row scrolls the page, a linked row follows its link on a tap and never on a swipe or a long press, one row is open at a time, and an open row closes on a tap outside it or on it, on scroll and on Escape. The sides follow the reading direction. With reduced motion the row still follows the finger, and jumps to rest on release instead of springing.
- The `ouro-testing` kit adds `holdFrames()` (testing/frames.ts), which holds `requestAnimationFrame` and `performance.now()` still so a test decides when a frame runs: `step(ms)`, `until(done)` and `release()`. Use it to look at a spring mid-flight, or to catch it with a pointer, without depending on how fast the machine is. The frames are released when the test finishes, pass or fail, and a frame handed back to the browser can still be cancelled by the id `holdFrames` gave it.
- `commands.touchDrag` and `commands.touchStep` now wait, before a touchstart, until the frame at its point has the kit's watcher. Before, a touch into an iframe added just before it could fail with "the page did not handle the touchStart", because Playwright had not listed the new frame yet. They ask Chromium which frame is at the point, so an iframe in a shadow root, open or closed, or under a `pointer-events: none` overlay is found, and they never wait for other frames, so a slow, cross-origin or never-loading iframe elsewhere holds up no touch. If the frame at the point has no watcher within 5 seconds, the command throws without sending the touch and names that frame. It then waits up to 5 seconds more for the page to handle the touch, as before, so a touch can take up to about 10 seconds to throw. When a touch is not handled, the error also names each frame of the page, whether it was watched, and every call into a frame that failed and why. A lift into a frame that has gone is still sent, so no finger is left down, and the command throws naming that frame.
- `commands.touchDrag` and `commands.touchStep` resolve once the page has handled the touch event they sent, and throw after 5 seconds if it has not, naming the event and the touch events the page did handle. Before, a test that read its touch listeners as soon as a swipe returned could miss the touchend or a touchmove: once the page scrolls, Chromium hands it the rest of the gesture without waiting. A `touchStep` gesture that scrolls is slower for it: each `touchMove` step after the scroll starts takes up to about 200ms, the rate at which Chromium hands a scrolling page its touchmoves, so the finger moves slower and a test that depends on its speed at lift may change. `touchDrag` waits once, after the touchend, and its speed is unchanged. While a gesture runs, both commands keep passive touch listeners on the window of each frame.
- Touch commands report unavailable observations, canceled moves and replaced target documents instead of mistaking them for Chromium's first-move slop. The slop exception requires a reported active gesture in the target document and no contradictory event; an unavailable unrelated frame still does not block it. Terminal touchcancel remains a valid lift. Existing time bounds and recovery behavior are unchanged.
- A toast now follows the finger or mouse that swipes it: it moves 1:1 once the pointer has travelled 10px, and that first 10px chooses sideways or down. A quick flick dismisses it however short (before, only a swipe past 40px did, and a flick did nothing); a release more than 40px from rest still dismisses it, unless the pointer was moving it back. Anything else springs back from where it was let go, at the speed it was let go, and can be caught again on the way. Pulled up, the one way it cannot leave, it follows less and less. A dismissed toast fades on the way it was thrown instead of sliding down.
- Toasts no longer animate `height` when the stack fans out, and their slide takes 300ms on the ease-out curve instead of the 750ms spring. A toast's `transition` is now `transform, opacity`; the swipe moves it with the `translate` property, so app CSS that set a toast's `translate` or read `--toast-swipe-movement-x`/`-y` or `data-swipe-direction` on it no longer has an effect. A toast no longer gets `data-swiping` either. In their place a toast dismissed by a swipe has `data-ouro-swiped`, and one that is springing back has `data-ouro-settling`.
- A press on a toast's action or dismiss button holds a toast that is still springing back, so the tap lands on the button.
- The toast's action and dismiss buttons show their hover color only for a mouse (`pointer-fine:hover:`), so it no longer sticks after a tap on a touch screen.
- Content inside a toast marked `data-swipe-ignore` or `data-base-ui-swipe-ignore` still starts no swipe, as do its buttons, links and inputs.
- Toasts set `touch-action: none`, so on a scrollable page a swipe dismisses the toast instead of scrolling the page and cancelling the swipe.
