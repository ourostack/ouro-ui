# Changes in this release

- New: [`ouroBuildSource()`](registry/ouro/lib/ouro/ouro-build-source.ts "verify:testExists(scripts/ouro-build-source.test.mjs::the ouroBuildSource plugin's tests pass and cover every line, branch and function of its own file)") is a Vite plugin that serves the running app's git state (branch, commit, dirty state, commits behind the official branch, worktree name, service files) as JSON at a `__ouro/source` route during `vite dev`, for a host app's dev tooling (such as BuildChip) to read without its own git shelling.
- Fixed: Button's label stays above its squircle-fallback surface in painting order; the surface now takes `zIndex: -1`, matching Badge, Card, Toggle, Dialog, TextField and ThemePicker's existing fix for the same non-positioned-label case.
- Fixed: Button's root carries `isolate`, as Badge's, Card's, Dialog's, Toggle's and ThemePicker's already do, so the surface's `zIndex: -1` stays contained within the button's own stacking context; without it, the surface escaped behind the page's own content and a translucent ancestor could paint over it, muting its fill and failing color-contrast on the label.
- Changed: Avatar cuts the notch round its presence dot from the surface's clip path while a dot is drawn, in place of a radial-gradient mask.
- New: Button takes `variant="glass"`, a Liquid Glass capsule 40px tall (a circle for an icon) that stays pressed while the popup it opens is open, and draws solid under reduced transparency or more contrast ([test](registry/ouro/components/ouro/button/button.glass.test.tsx "verify:testExists(registry/ouro/components/ouro/button/button.glass.test.tsx::Button glass > is 40px tall, and a circle when it holds only an icon)")).
- Fixed: [Button's label no longer re-anchors an app's absolutely placed children](registry/ouro/components/ouro/button/button.label.test.tsx "verify:testExists(registry/ouro/components/ouro/button/button.label.test.tsx::Button label > is no containing block, so an absolutely placed child anchors to the button)"), because the label is its own stacking context instead of `relative`, so it still paints above the touch target.
- Fixed: Carousel no longer announces the wrong slide when a second press follows close behind an earlier one, before the first press's stability check has fired.
- Fixed: the Ouro AX census's walkers [run on a product's own `typescript` again](scripts/ouro-census/manifest.node-test.mts "verify:fileLine(scripts/ouro-census/manifest.node-test.mts, /a vendored file imports only Node's built-ins, the product's own typescript and other vendored files/)"); v1.3.506 had them import `typescript7`, which a product does not install, so its census failed with `ERR_MODULE_NOT_FOUND` (#3380).
- New: [Command takes `recents`](registry/ouro/components/ouro/command/command.recents.test.tsx "verify:testExists(registry/ouro/components/ouro/command/command.recents.test.tsx::Command recents > is entered with Down, walked with Left and Right, and left with Up or Escape, which does not close the palette)"), a single row of chips under the empty search that Down enters, Left and Right walk, and Up or Escape leaves, with no command highlighted while focus is in the search.
- New: [Dialog reads its enter and exit duration and easing from `--ouro-dialog-duration`, `--ouro-dialog-ease`, `--ouro-dialog-exit-duration` and `--ouro-dialog-exit-ease`](registry/ouro/components/ouro/dialog/dialog.test.tsx "verify:testExists(registry/ouro/components/ouro/dialog/dialog.test.tsx::motion > reads its enter and exit timing from the --ouro-dialog tokens, on the popup and the backdrop)"), on the popup and the backdrop, so an app sets one timing for every dialog, Command and Lightbox; the defaults are the old 300ms in and 200ms out.
- Fixed: NavigationRail's count badge centres its digits on their own glyph box with flex, instead of a line-height, so the digits sit centred in the pill whatever the badge's font leaves above its cap height.
- New: Ouro check reports `near-miss` when separate surfaces sit closer than `--ouro-gap-min` without touching; opt out with `data-ouro-allow="near-miss"` and a reason.
- Changed: FamilyBar, CodeBlock, Chart, ToggleGroup, Tabs and ScrollArea no longer fade where a row or region scrolls on, `lib-scroll-fade` and its `ouro-scroll-fade-*` keyframes are gone, and TimeGrid's sticky day header is a blurred glass bar over the hours that scroll beneath it, solid under `prefers-reduced-transparency` and `prefers-contrast: more`.
- New: `data-ouro-veil` covers a state nobody has designed yet with a solid "Not designed yet" layer (ouro-base), and Ouro check skips what is inside it.
- Docs: SnapPiP says an app with a tile grid passes the grid as `keepOut`, so a corner move lands clear of the faces.
- New: `squircleCorners()` (item `lib-squircle-corners`), a PostCSS plugin that draws squircle corners at build time in engines without `corner-shape`, and sets `corner-shape: squircle` where the engine has it; the page runs nothing of it.
- Fixed: ThreadLayout drops the thread rail's own `border-s` below the breakpoint where the conversation pane hides, since the rail would otherwise sit alone against the layout box's own edge and double its line.
- Fixed: the ThreadLayout and ThreadRail stories wrap their Composer in a bordered, padded box, since an unwrapped Composer's own end border landed on the rail's `border-s` line.
- Fixed: [TimeGrid's all-day row keeps its last event at least the minimum gap below the sticky day header](registry/ouro/components/ouro/time-grid/time-grid.tsx "verify:fileLine(registry/ouro/components/ouro/time-grid/time-grid.tsx, /lanes \* 1\.5 \+ 0\.75/)"), so the German, Japanese and Arabic locale stories no longer trip Ouro check's `near-miss` rule there.
- Fixed: [TimeGrid draws its sticky day header as glass over the hours scrolled beneath it, with no fade](registry/ouro/components/ouro/time-grid/time-grid.test.tsx "verify:testExists(registry/ouro/components/ouro/time-grid/time-grid.test.tsx::TimeGrid > draws its day header as glass over the hours scrolled beneath it, with no mask on the scroller)").
- TimeGrid: the day view's background-events lane no longer draws a dashed edge beside the person's own events, which nothing explained.
